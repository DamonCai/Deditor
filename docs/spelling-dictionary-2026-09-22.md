# 应用用户词典与文档忽略词（2026-09-22）

用户授权补齐独立词典与忽略词管理。采用应用管理词条、现有 WebView 系统拼写检查负责判断其他正文的本地方案；不新增远程服务或下载词库，不调用系统 Learn/Unlearn，不读取/修改用户系统词典文件。

## 产品行为

写作设置新增“用户词典与忽略词…”入口：

- 用户词典适用于全部文档；忽略词只适用于当前文档。支持当前选词预填、输入词条、添加、移除、筛选、键盘与 Esc。
- 词条按 Unicode NFC 规范化，不区分大小写；接受单个词，可含字母、数字、撇号、连字符及下划线，不把句子当作一个词条。保留正文原大小写与原字节。
- 具名文档按文件绝对路径保存忽略词；另存为/重命名时复制到新路径，原路径仍保留自己的列表。未命名文档按标签暂存于本会话，首次保存时转入文件配置；关闭未命名标签清理会话列表。
- 增删后阅读编辑的命中词使用不进入源码的 ProseMirror inline decoration 设置 `spellcheck=false`；删除词条后取消该标记。普通正文、标题、表格及跨粗体等格式的词生效；代码块、行内代码和保留源码不被当作正文词条处理。
- 总“系统拼写检查”关闭时不生成词条标记，词条仍保留；管理面板可直接开启检查。管理操作不进入文档撤销历史、不修改正文，不添加 CSS 伪造红线显示。
- 中文/英文文案、亮暗主题及窄窗布局均已实现。实际平台是否显示拼写标记仍由对应 WebView/系统语言支持决定。

## 应用持久化与并发

Rust `spelling_dictionary.rs` 仅访问当前应用数据目录的 `spelling-dictionary.json`。读—修改—临时文件写入—替换—广播受进程互斥锁保护，各窗口发送独立操作而非覆盖整个旧快照；递增 revision 防止慢读取或过期广播覆盖新词条。损坏 JSON 报错且不覆盖原文件。

读取和保存失败在面板显示，原有词条保持；新增输入保留供重试。另存为传送失败保留当前会话忽略词，可用“重试”写回。列表按当前文档作用域显示，应用自身 UI 不枚举系统词条。测试命令只接触自建临时目录。

## 输入开销

- 词典为空或检查关闭时不遍历文档。
- 纯选区事务直接保留原插件状态。
- 正文事务映射已有标记，只重查触及范围内的文本块和单词边界；格式标记事务也处理，防止转为行内代码后留下接受标记。
- 词条/作用文档/开关改变时重新计算该文档的接受范围。这是低频设置操作，不放到逐键全文扫描路径。
- 组词期间延后设置引起的刷新，compositionend 后再应用；本条不代表真实中文候选验收完成。

HTML 标准中的 `spellcheck` 是浏览器检查资格提示；依据：[MDN spellcheck](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/spellcheck)。这里通过正文实际标记联动现有检查，而非只提供无作用的词条列表；实际原生红线抑制必须另行观察。

所有 Rust 专项使用独立随机临时目录并通过 RAII 清理；不依赖修改文件权限，不访问应用日常配置或系统词典。
