# 阅读编辑基本操作与光标恢复（2026-09-12）

## 范围与复现证据

用户在混合列表空项按 macOS 删除键后，光标回到前面的引用链接；要求横向检查基本操作。本次范围为列表删除/回车/方向键、行内源码进入退出、跨片段选区以及撤销和源码同步。只使用自建样例，不提交推送。

用户补充确认空项原本就在原文中；最终验收以原文空项为起点。原截图的“单次删除直接回到引用链接”在最小样例和长文样例中未稳定复现；不能将以下共性问题直接等同于该截图的已证实根因。

已稳定复现并修复：

- 打开行内代码源码，再选择后面的空列表项，旧实现会把光标恢复到前一项 `水电`。`tests/artifacts/basic-baseline.log` 保留修复前失败证据。
- 编辑行内源码后离开，旧实现仍会把空项光标恢复到前面的彩色文字。跨片段选区也受同一路径影响。
- 前面一块正文缩短时，源码同步沿用旧的文档字符位置，目标正文的选区落入后面的引用定义。`tests/artifacts/basic-sync-before.log` 为旧同步代码的失败证据；原生逐步撤销时也观察到引用定义意外打开。

## 修改

`document.ts` 按实际文本序列对齐源码与编辑节点，不再要求 Markdown 文本叶子和格式拆分后的文本节点数量相同。覆盖换行、HTML br、转义、实体（含组合字符）、空列表项。按不可变节点和 AST 缓存映射；不能验证的归一化片段不留下猜测偏移。行内源码只能在有确切两端映射的文本范围内展开。

`inlineSource.ts` 在收起源码时保留未改动前缀/后缀里的文档位置，分别映射选区两端。编辑过的源码需要重解析时，也保留未改变的相邻空项位置。

`MarkdownVisualEditor.tsx` 同步内容时，依据新旧文档差异移动未改动区域的光标和选区，避免前文长短变化把旧数字位置推入引用定义。
