# Markdown 阅读编辑与实时预览呈现一致性（2026-09-11）

用户反馈两种模式展示不同，并要求类似文档产品的 H2 级别提示。本次直接以真实 Preview 为基准修复；不将历史自动化通过视为视觉验收。

## 原因与实现

- 原来的阅读编辑沿用 Crepe 字号、行距、列表、表格、图片和代码块样式，而实时预览使用 `src/preview.css`。旧隔离测试页还错误地在“实时预览”位置挂载 MarkdownVisualEditor，未真正对照两个组件。
- 两种模式现在共用 `preview.css` 的正文规则及按栏宽响应的布局；阅读编辑仅适配节点包裹层和编辑控件。两边字体缩放同步，HTML iframe 与 XMind 专用界面保持隔离。
- H1–H6 左侧添加轻量级别提示，使用不可选择的 CSS 伪元素，不创建文档节点；只读和导出不显示。标题转换后提示随真实级别变化。
- 普通代码使用同一 `renderMarkdown` / Shiki 输出；点击或键盘 Enter 进入 CodeMirror，Esc / 离开恢复呈现。语言与复制控件浮动显示，不增加正文高度。图表、公式复用实时预览渲染链路，并补齐 `puml` / `uml` 别名。
- 修正图片被上游最小高度强制放大、图片居中、表格多余段落间距、嵌套列表间距、行内公式颜色和隐藏源码控件占位。
- 本次操作回归发现：撤销后上游同步生成标题 id，会被保真层误认成正文变化，导致连续标题间插入空行。保真比较现忽略标题生成 id，仍比较级别、文本和标记；撤销恢复原文。滚动回调改为写入已绑定的会话，不以过期文档内容重新同步并清空重做历史。

## 五轮验证

轮 1 — 用例：真实 Preview / 阅读编辑同宽呈现对照。
  期望：标题、段落、引用、列表、表格、代码、行内及块级公式、Mermaid、图片一致。
  实测：自建 20 个正文块逐一对比高度、相对顶部位置；720px 窗口双栏各 360px，全部相同；宽窗口也检查正文基线与表格尺寸。代码 Shiki 内容另有集成测试逐字比较。
  结果：✅ 浏览器验证。

轮 2 — 用例：窄窗口、暗色、字号调整、H1–H6 边界。
  期望：按每栏宽度响应；提示不挤压正文；主题及字号一致；只读隐藏提示。
  实测：720px 下两栏均为 15px 正文、24px/20px 内边距，无横向页面溢出；字号增加后两边均为 16px、H1 均为 32px；暗色正文同为 rgb(203,208,217)。提示未进入原文。H4 输入单个 `# ` 得到 H1，撤销回到 H4。
  结果：✅ 浏览器及输入规则测试。

轮 3 — 用例：代码点击/键盘编辑、退出、撤销重做、只读、多标签和保存。
  期望：操作作用于正确位置；退出返回渲染；原文与保存相同。
  实测：中文代码编辑同步到对应行；新增代码展示、点击、Enter、Esc、失焦、只读、历史集成测试；连续标题撤销前后原文完全相同；滚动与撤销重做交错保留历史。浏览器切换真实实时预览确认 `.preview` 存在、阅读编辑卸载，切标签后保存快照与原文相同。
  结果：✅ 浏览器及集成测试。

轮 4 — 用例：用户报告的搜索后跳页、长文下方无法编辑。
  期望：关闭搜索后任意位置连续输入不覆盖文末、不自动跳页。
  实测：30 节自建长文先搜索文末再关闭，顶部连续输入前后 scrollTop 为 0/0，底部为 3971/3971；源文件对应位置包含输入，搜索目标保留。引用列表、保留源码块和代码光标原有回归保留。
  结果：✅ 浏览器及集成测试。

轮 5 — 用例：全量自动化、构建和其它文件类型回归。
  期望：Markdown 修复不影响 HTML、XMind、保存、导出、高亮和图标。
  实测：提交快照的最终结果见下方。浏览器自建 HTML 仍以 iframe 呈现；XMind 独立工具栏、内容和工作表可见。
  结果：✅ 提交快照的完整自动化及构建通过。
