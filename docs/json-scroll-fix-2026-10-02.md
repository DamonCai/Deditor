# JSON 右侧滚动条无响应（2026-10-02）

## 原因与修复

`inspectionMarkers.ts` 的书签概览栏绝对定位在编辑器最右侧，宽 8px、覆盖整个高度且 `pointer-events: auto`。没有书签时透明栏仍存在，会截获原生滚动条的拖动和该区域的滚轮事件。文件出现垂直滚动条后即可触发，不需要达到某个 JSON 大小阈值。

透明栏改为 `pointer-events: none`，实际书签标记单独保留 `pointer-events: auto` 和原有点击跳转。没有改变文件内容、解析、渲染规模或编辑行为。此组件用于所有源码编辑器，修复不限 JSON。

## 验证

只用本轮生成的样例；浏览器入口 `tests/json-scroll-review.html` 挂载真实 Editor，禁用原生 I/O，不加载用户文档和应用恢复状态。

轮 1 — 用例：294,782 字符、18,002 行 JSON 的右侧拖动。
  期望：滚动条响应拖动，书签点击可跳转，内容保持。
  实测：修复前右侧命中 `cm-inspection-strip`，从 (1276,80) 拖到 (1276,400) 后 scrollTop 仍为 0；修复后同位置命中 `cm-scroller`，同一拖动后 scrollTop=178836.5、首行约 9128。点击中间书签后到第 9001 行，清除书签正常，内容逐字符串比较不变。
  结果：通过，真实内置 Chromium 与专项组件测试。

轮 2 — 用例：空文本、`{}`、单行长 Unicode JSON，以及暗色 720px 编辑区域的大 JSON。
  期望：空标记栏穿透，边界书签可操作；大文件仍可拖动和滚动。
  实测：组件边界断言通过。真实浏览器 3,007,782 字符、180,002 行样例拖到约 124837 行，右侧滚轮后到约 124910 行，反向拖动回约 47209 行；内容不变。
  结果：通过。

轮 3 — 用例：两个编辑器各自书签，插入行后点击书签、清除和销毁。
  期望：位置随编辑映射、实例互不影响，销毁移除标记栏。
  实测：组件专项通过；左侧书签由第 2 行映射到第 3 行，右侧仍跳第 2 行；清除左侧不影响右侧。
  结果：通过。
