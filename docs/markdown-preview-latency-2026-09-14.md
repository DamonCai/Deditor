# 实时预览原生输入卡顿（2026-09-14）

## 范围与复现

用户在源码跳动修复后继续反馈“实时预览，编辑的时候非常卡”。本次只处理输入时预览整篇更新的开销；沿用此前自建的约 4,470 行、405KB 复杂文档，包含 100 组正文、长表格、代码、数学、引用、任务、脚注和 10 个 Mermaid 图。没有编辑用户原始文件。

按用户要求在 macOS 原生应用验证。独立源码副本 `/tmp/deditor-preview-latency-20260914` 从 `4a5c9b7` 建立，加上此前连续标题修复与本次预览改动。它没有纳入工作区进行中的分栏／搜索等修改。测试依赖包复用，生成的 `.cache` 独立，避免并行测试覆盖临时编译文件。

仅在副本中加入原生采样模块，记录 Markdown 渲染、HTML 处理、提交和动画帧间隔；正式源码没有采集入口。旧包与改进包均在同一文档第 943 行、相同坐标逐键输入 `7`、`8`、`9`。旧包每次替换整页，未变化的图表也重新生成；原生采样出现约 4 秒的画面刷新停顿。

## 实施

- `MarkdownPreviewCache` 按预览顶层块缓存共享清洗结果，只保留当前文档条目。仍调用原 `markdownDisplayHtml`，保留文件链接、图表源码、iframe 限制及安全清洗规则。
- 行号与块内容分开缓存。仅移位的 `data-line` 更新到原 DOM，插入换行不会使后文代码和图表全部失效。内部映射标记在挂载时移除，不新增排版包裹。
- `MarkdownPreviewDocument` 复用未改动的节点，按顺序插入新块／删除旧块，保留已生成 SVG、图片和 details 展开状态。重复相同块分别维护节点，避免把两个段落合并成同一节点。
- 保留仍在挂载的图表异步工作；内容删除、主题／路径上下文切换、DOM 淘汰和卸载时清理。主题切换仍重新生成对应显示内容。
- Preview 在提交前丢弃过期结果，再更新缓存；原有滚动来源保护、隐藏预览延后更新、目录、搜索和本地图片处理继续保留。

没有改正文 CSS，没有改 Markdown 语法或高亮算法，也没有把实时预览改成手动刷新。整篇 Markdown 解析仍存在，不能据此声称所有长文输入开销已消除。
