# Markdown 非导出项检查（2026-09-12）

用户要求排除导出，检查输入、直接编辑、长文、图片和语法兼容。本次检查并修复可复现问题，不代表实现了全部 Typora 功能；不提交或推送。既有字体统一改动保留，独立 XMind 修改未纳入隔离验证。

> 本文记录检查当时的缺口。随后用户要求执行，直接编辑、简写、本地图片整理和已编辑片段收起已有后续实现；请以[实施记录](markdown-extended-editing-2026-09-12.md)核对最新状态。

## 检查结果

| 范围 | 证据与结论 |
| --- | --- |
| 输入与历史 | 完整阅读编辑集成覆盖正文/表格/代码/保留块/源码的组合输入历史、取消、延迟提交、选区、撤销及模式切换。浏览器实际输入 `x` 后一次撤销恢复原文。真实 macOS 拼音候选和 Windows 仍未完成验收，本次没有新的原生通过证据。 |
| 复杂块直接编辑 | 新增可重跑探测：含脚注的普通段落加定义生成 2 个保留源码块、没有直接正文段落；提示块生成 1 个保留源码块。显示与模式切换保真通过，但直接编辑缺口仍存在。 |
| 长文 | 实测并优化“未改动行内片段的收起”，详见下表。修改过的片段仍走完整重解析；输入、查找、跨块选择与大图表布局的完整端到端性能尚未全部覆盖。 |
| 图片 | 修复转义括号被当路径分隔符、重命名引号破坏 HTML、HTML 实体路径后续重命名失败、Windows 大小写不一致漏匹配、编码空格目录比较不准，以及新名称含不配对括号导致 Markdown 图片失效。POSIX 大小写仍严格区分，不相关的重命名不改原文。 |
| 图片流程 | 已有本地图片目录、尺寸和路径维护；当前“上传”回调实际保存本地文件。图床服务、按文档的 Typora 图片元数据规则、批量图片整理没有实现，未将其算作已支持。 |
| 语法兼容 | 实际渲染探测确认 `==高亮==`、`H~2~O`、`X^2^`、`:smile:` 仍为普通文字；对应 HTML mark/sub/sup 可以显示。原文都保持不变。脚注悬停预览尚未实现。 |

## 长文测量

`scripts/perf-markdown-inline.ts` 使用真实 ProseMirror 与当前行内控制器，在 JSDOM 中各运行 5 次展开/收起。样例含中英文和强调；此测量没有浏览器绘制和原生输入法成本，不能当作整篇编辑器输入延迟。

| 段落数 | 字符数 | 收起中位数：修改前 | 修改后 |
| --- | ---: | ---: | ---: |
| 100 | 3,389 | 11.40ms | 0.54ms |
| 500 | 17,389 | 42.63ms | 0.45ms |
| 1000 | 34,889 | 78.29ms | 0.55ms |

每组完整解析次数从 6 次降为 1 次（初次加载）。只在内容与进入时一致时恢复缓存片段；修改内容仍使用原有重解析路径。浏览器实际进入 `**加粗**` 再按 Esc，源码完全不变，滚动位置保持 0；输入 `x`、收起再撤销恢复原文。
