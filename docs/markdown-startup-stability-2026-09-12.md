# Markdown 加载与模式切换稳定性（2026-09-12）

## 用户反馈与确证原因

用户报告 `MilkdownError: Context "nodes" not found`。在当时仍运行的 5173 服务上，新建测试页和刷新均持续复现，排除了仅有旧页面内存状态的问题。

通过自建诊断页捕获调用栈，并检查服务实际返回的模块内容，确认注册节点的 utility 模块和编辑器核心引用了不同 URL：核心上下文来自带 `?v=5430cdce` 的 chunk，utility 内部却导入同一 chunk 的无版本 URL。Milkdown 用 Symbol 标识上下文，浏览器把不同 URL 当成两个模块，因此显示名称都叫 `nodes` 也不能共享注册表。

旧服务共享 `node_modules/.vite`，第二个开发服务及启动脚本的清缓存操作都可能替换正在使用的依赖文件，令内存模块图和磁盘产物不一致。这里确认的是实际模块身份冲突；不能从它推断生产包也有同一缓存问题。

## 修复

- `vite.config.ts`：每个开发服务使用独立临时缓存，关闭时清理自己创建的目录；预先包含 Markdown 编辑所需的 Milkdown 入口，固定相关核心模块的解析；限制扫描入口，避免验证产物进入依赖扫描。生产构建保持原路径。
- `MarkdownVisualEditor.tsx`：取消初始化后等待创建流程结束再单次清理，旧实例不能清空替代实例的桥接。创建失败时避免调用 Milkdown 在 `OnCreate` 状态下永久轮询的 destroy；释放可能已经创建的视图。新增中英“重新加载编辑器”入口，重试读取现有草稿，技术信息放入可展开详情。
- 浏览器连续切换又复现了独立空白页错误：共享显示组件同时传了 `dangerouslySetInnerHTML` 与 React 子元素。`MarkdownDocumentSurface` 将自定义样式节点置于正文表面之外，恢复 HTML 预览与可编辑宿主的兼容性。
- 无可见高度时不再用目录滚动测量覆盖当前光标对应的章节。

## 验证与边界

- 原来失败的 5173 环境在配置更新后恢复加载。
- `npm run test:markdown-startup` 通过：两个同时运行的真实 Vite 服务，其 Crepe、schema utility、core 实际响应引用完全一致的核心 URL；第二个服务启动、关闭都不会替换第一个服务的模块身份，关闭仅删除自身缓存。此检查已纳入 `test:all`。
- 新增集成用例用同名、不同 Symbol 的上下文复现缺失 `nodes`，验证错误重试后原文、输入、保存和撤销；另覆盖延迟创建期间取消、替代实例所有权、StrictMode、自定义 CSS 下 Preview/Visual 往返。最终固定快照执行 `DEDITOR_TEST_FILTER='^(shared surface:|lifecycle:)' node scripts/test-markdown-visual-integration.mjs`，5 项通过。
- 固定代码快照浏览器验证：普通文档输入 Z 后，10 轮源码→实时预览→阅读编辑，6 轮标签与主题往返，始终只有一个编辑区、无错误提示、全文精确一致；保存快照一致，撤销恢复原文。
- 6303 行、152241 字符自建文档完成两次模式往返，阅读编辑恢复后全文一致、没有加载错误。大文档重建仍慢，浏览器控制期间出现超时，随后读取状态确认操作已完成；不计为长时压力或流畅性全面通过。
- 固定快照 TypeScript 与生产构建通过。构建保留既有大包提示。
- **最终全量集成未全部通过**：共享工作区另有持续修改的脚注相关功能，固定快照在 `shorthand parity` 的 `sup` 对照失败，实际比期望多出 `[2][1:1]`。没有删掉或放宽该断言，也没有把过滤后的针对性通过当作全量通过；需由脚注功能继续核对。较早中间快照 95 项通过不覆盖后续整合内容。
