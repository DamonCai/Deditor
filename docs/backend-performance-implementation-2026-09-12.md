# 后端保存与历史优化（2026-09-12）

用户要求实际实施后端优化。本次锁定 Markdown 保存、草稿历史去重及状态落盘验证；没有调整页面，也没有提交推送。

## 已实施

- `markdown_history.rs` 为已读取的历史正文增加精确内容缓存，最多 32 条，正文和路径容量合计最多 32MiB。仍核对文件身份、长度、mtime/ctime 纳秒；外部改写、替换或删除使缓存失效。只在读取前后签名一致时填充缓存，不用单一散列值决定是否丢弃历史版本。缓存项随历史清理移除。
- Unix 缺少细粒度 ctime 或非 Unix 环境保守回退原来的磁盘读取。当前去重收益只在本机 macOS 测得，不能推断 Windows 同样提速。
- 保存前读取旧文件时，已知超过历史 2MiB 上限就跳过；实际读取也最多消费 2MiB+1，以覆盖文件增长及元数据不可用。小文件的 UTF-8 和读取失败语义保持不变。
- 历史列表先筛选再复制，避免复制无关条目。
- 状态持久化逻辑抽到 `markdown_state.rs`，供真实文件回归及独立性能脚本直接调用。最终仍使用原来的完整 JSON 解析，借用正文执行历史检查，未改变持久化格式或前端调用契约。

主文档保存仍按旧历史、主文件写入、新历史顺序执行。状态仍先写临时文件并重命名，再保留独立草稿。主保存或状态落盘失败仍返回错误；历史失败仅警告，不否定已经成功保存的文档或状态。

## 实测

`bash scripts/perf-backend-history.sh` 固定旧版本 `34b8e35745f9688473182b5734a4235540d92e3c` 的历史实现，与当前实际后端代码进行同轮对照。自建临时数据，1/20 个 1MiB 文档，普通/转义正文、干净/未保存状态，共 8 场景，各 5 次，表中为中位数。

| 场景 | 旧实现 | 当前实现 |
| --- | ---: | ---: |
| 20 个普通文档重复历史核对 | 2.475ms | 0.589ms |
| 20 个转义文档重复历史核对 | 2.735ms | 0.592ms |
| 20 个普通未保存文档：状态写入、重命名、解析与检查点 | 14.141ms | 12.153ms |
| 20 个转义未保存文档：同上 | 71.643ms | 67.556ms |
| 20 个转义干净文档：同上 | 63.219ms | 63.063ms |

另以同一自建文件交替比较旧全文读取和当前有界读取，11 次中位数：20MiB 文件额外历史读取 4.2473→0.0591ms；1MiB 文件 0.1315→0.1149ms。该数字只代表历史读取环节，不能当作整个保存耗时。

结果均为本地暖文件缓存下的 Rust 工作，不包含 JSON 生成、IPC、页面渲染、fsync 或首次历史创建。首次审计中的 10.400→0.642ms 使用另一份中文/换行样例及独立采样，不与本表混算提升比例。干净文档及状态解析基本持平，不宣称已优化整份状态传输。

## 验证与范围

- 351 项与旧处理逻辑的语义对照通过，覆盖异常字段、重复键、孤立 Unicode surrogate、数值溢出、过深 JSON、转义及未命名文档。
- 真实临时文件回归覆盖历史去重、改写并恢复 mtime、替换/删除/非法 UTF-8、缓存容量、读取限额、原文精确保存、保存前后历史、主写入失败和历史失败、状态完整落盘以及关闭后快照不恢复已关标签。
- 没有读取真实用户 app_data，没有启动原生测试应用；不是原生 UI、真实输入法或 Windows 验收。

最终 `cargo test --release` 全部 30 项通过（包含 8 项现有后端基准），主程序和文档测试无用例；`cargo build --release` 通过。不是桌面安装包或原生 UI 验收。验证产物在被 Git 忽略的 `tests/artifacts/markdown-backend-performance-2026-09-12/` 和前次审计的 `tests/artifacts/markdown-backend-performance-audit-2026-09-12/`；`verified-source.json` 记录已验证源码哈希，构建后核对未变。

## 尚未实施

全量状态正文传输与解析、过期工作区搜索取消、Unicode 搜索及批量替换的重复分配仍待独立实施。一次尝试的 RawValue 定向状态解析在转义脏文档上产生明显退化，已撤回，依赖配置也恢复原状；最终代码仅保留已测出收益的历史和旧文读取优化。
