# Markdown 局部更新与隐藏源码性能优化（2026-09-12）

用户担心 Markdown 操作卡顿，本次在此前原生光标与初始化取消保护之上，继续减少输入路径的重复工作。没有调整字体、正文样式或 Markdown 保存格式。

## 已修改

1. **控件按变化区域更新**：原先任意按钮的显示状态、块样式或子节点变化都会扫描全文按钮和列表标签；现按 MutationObserver 记录，只处理变化节点、新增子树和受影响的祖先任务。任务正文的字符变化同步辅助阅读名称，嵌套任务更新父任务名称；任务转普通列表时清除旧复选框语义，保留其他控件的语义。初始化和编辑权限变化仍执行完整检查。
2. **关闭目录时停止计算目录**：打开时读取当前文档，保持最新标题和跳转位置，不在每次输入后计算看不见的目录。
3. **隐藏 Markdown 源码延后同步**：阅读编辑时，隐藏的 CodeMirror 不再处理每次全文更新；重新激活源码时，在绘制前一次同步最新内容。保存、撤销继续使用文档 store 和共享历史；隐藏源码的延迟位置回调和卸载不能覆盖阅读编辑的光标。HTML、普通代码以及显示中的分栏源码仍沿用实时同步。

## 测量

控件基准 `npm run perf:markdown-controls` 使用自建 DOM，各规模预热 5 次、采样 30 次。仅测局部控件显示状态变化的 DOM 处理，不含真实浏览器布局或 IME。

| 任务数 | 修改前中位数 | 修改后中位数 |
| --- | ---: | ---: |
| 100 | 1.070ms | 0.044ms |
| 500 | 5.451ms | 0.029ms |
| 2000 | 29.110ms | 0.026ms |

浏览器自建复杂 Markdown：152241 字符、6303 行、500 个表格及嵌套列表、公式、图表等。相同末段位置依次按 `q`、`w`、`e`，从按键到第二个动画帧：

| 版本 | 三次测量 | 中位数 |
| --- | --- | ---: |
| 本次修改前（已有原生光标） | 116.2 / 87.5 / 84.7ms | 87.5ms |
| 仅局部控件与目录优化 | 95.9 / 89.1 / 82.7ms | 89.1ms |
| 加上隐藏源码延后同步 | 78.8 / 70.5 / 69.8ms | 70.5ms |

最终三点中位数约降低 19%。单靠控件优化在这份以普通表格为主的样例上没有证明稳定的整页输入改善，不能将局部基准倍率当作整页提升。测量受机器负载、帧调度、文档类型影响，只有三个输入样本，不是固定性能承诺，也不是 Typora 对照或原生中文输入法验收。70ms 级输入和大文档数秒级模式重建仍有优化空间。

## 验证

- 46 项 Markdown 核心、85 项阅读编辑集成、142 项通用组件回归通过；TypeScript 与生产构建通过（仍有既有大包提示）。
- 新增/增强：500 项任务中的局部更新不扫描文档根；任务字符编辑、嵌套新增/修改/删除、复选框转普通列表、其他控件语义保留；关闭目录后修改、重开与标题跳转；隐藏源码不随阅读输入更新、保存读取最新原文、激活后同步；多次外部内容替换和隐藏源码卸载后保持最新内容及阅读光标。
- 浏览器最终输入全文严格等于修改前相同按键得到的全文，输入滚动位置保持 286950.5。保存快照完全一致；源码可见末段含新增 `qwe`；跨模式撤销到原文、重做回编辑结果均完全一致。
- 两次返回阅读编辑后全文完整，再次撤销恢复原始复杂文档。部分大文档工具点击超时后，随后的 DOM 核对证明动作已完成；这不能算切换足够流畅。
- 最终完整复杂文档与真实 Preview 的 465 项同宽呈现检查通过，差异为空。
- 本次未启动原生测试应用；真实 macOS/Windows 候选输入与长时间内存压力测试仍未验收。此前开发页面崩溃的边界继续见 [原生光标与长文记录](markdown-native-caret-long-document-2026-09-12.md)，不以本次局部优化宣布全部解决。
