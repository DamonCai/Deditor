# 阅读编辑 Enter 与撤销修复（2026-09-12）

## 范围与复现

用户反馈：输入三个反引号和 `json`，Enter 正常转成代码块，但撤销有时恢复完整标记，有时只剩三个反引号。本次限定检查 Enter 转换、段落／列表／代码换行，以及紧随其后的撤销、重做和继续输入；保护并行进行的表格、格式、粘贴和 XMind 修改，不提交推送。

修复前的真实组件测试固定时钟后稳定复现：语言输入到 Enter 间隔 0ms，撤销连同 `json` 删除；间隔 1000ms，撤销保留 `json`。两种情况光标均落到标记段落开头。原因是共享 Markdown 历史把 750ms 内相邻修改合并，Enter 转换没有单独的操作边界。

横向补测还发现：文末新增空段落被序列化成空字符串，未进入共享历史；上游段落序列化明确丢弃最后一个 hardbreak，使行尾 Shift+Enter 同样没有独立记录。

## 修改

- 在阅读编辑的键盘捕获和 `beforeinput` 路径建立 Enter 前后历史边界，包含内嵌 CodeMirror；组词中的 Enter 不拆分 IME 历史。
- 共享历史在可用时保留编辑前后的不可变文档结构、原文索引和选区。文本输入仍按原分组规则合并，撤销后恢复准确的段落、空段落及双向选区。历史上限仍为 500 组，不复制整篇原文字符串。行内源码展开属于临时投影，不写入这些快照；该路径继续从保真原文恢复。
- 新增空段落写入对应换行；段落末尾的显式 hardbreak 序列化为 `<br>`，避免无后续文字时被丢弃。未修改段落的原文保持不变。
- 原生首包实际复测进一步发现：移除代码输入框后，模型选区虽然恢复，DOM 焦点丢失，立即输入 `X` 会出现在下方。最终修正只在历史恢复移除了当前焦点节点时把焦点交回正文，保留正常文档更新和现存输入框的焦点行为。
