# XMind 组合输入目标稳定性核查

本轮针对中文组合期间缩放、平移和布局刷新是否替换原生输入目标进行独立代码与组件核查；未操作原生 UI，也不重复此前 2,736 组输入框几何矩阵。

`XmindCanvas` 的编辑框位于独立草稿渲染位置，主题节点保留 topic id 作为 key；相机或场景刷新不会自行更换 textarea。新专项 `scripts/test-xmind-composition-target.mjs` 使用实际组件，在合成 composition 期间依次触发缩放、平移、320×240 窄窗 resize、主题和前置兄弟节点布局变化、异步字体就绪，并分别发送 `isComposing=true` 与 `keyCode=229` 的 Enter/Escape。九次更新均保持同一 textarea、焦点、选区和草稿，未提前提交文档。销毁后 ResizeObserver 全部释放。

专项发现独立的确定重入：普通 Enter 调用 `commitEdit` 后将焦点移到画布，紧接着的 blur 在 React 提交新状态前再次调用旧回调，同一标题命令发送两次。现仅在第一次提交前同步设置既有结束标记，使 blur 不再重复提交。新编辑会重置标记；后续草稿直接 blur 仍可提交，Escape 及其 blur 仍不提交。

修前新增专项在“一次标题命令”断言失败，记录到两个相同的 `你好` 命令；修后通过。文档模型原本已对相同标题去重，因此本轮**未复现丢字、重复历史或双次撤销**，修复结论仅为阻断同一草稿的重复提交回调，不扩大为这些数据问题。

定向验证：

- `node scripts/test-xmind-composition-target.mjs`：九次组合期间更新、最终中文一次提交、下一次 blur 提交、Escape 取消、原始样例未改及卸载清理通过。
- `node scripts/test-regression.mjs --round=21`：2 项通过，覆盖连续草稿与最终文本保存/撤销/重做，以及跨文件资源和联系归档的精确恢复。

以上测试使用自建样例和合成 DOM 事件，只证明组件目标稳定性及提交生命周期。系统候选窗口定位仍须主端的真实输入法候选画面；不得以 textarea 身份、DOM 几何或中文提交正确替代该原生验收。本轮未修改候选坐标、输入法处理、缩放规则或保存语义；未自行运行全量、构建或提交。
