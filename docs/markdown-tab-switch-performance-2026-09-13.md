# 顶部文件标签切换性能（2026-09-13）

范围：用户反馈点击顶部不同文件切换较慢。本次定位并优化 Markdown 阅读编辑的重复初始化；不扩大到首次打开文件、HTML/XMind 的渲染实现或此前完整路线图。

## 原因与实现

`App` 原来用 `key={activeTabId}` 挂载唯一的 `MarkdownVisualSlot`，每次换文件都销毁 Milkdown/ProseMirror 和整份阅读 DOM。CodeMirror 与预览已有最近标签保留机制，阅读编辑没有。

新增 `MarkdownVisualHost`，复用既有八标签 MRU 规则，仅保留实际访问过的阅读文件。顶部切换在当前 render 就显示目标；后台槽隐藏且 inert，不接管活动 bridge，不把旧正文写回新内容。源码模式从未访问阅读的文件、HTML、比较标签不初始化阅读编辑器。关闭文件与 MRU 淘汰释放实例，文档共享历史继续由原 session 管理。`MarkdownVisualSlot` 使用 memo，避免更新 MRU 时重复渲染所有隐藏槽。

原生初版验收实际发现：切到 alpha 后 Cmd+Z 被 WebKit 送到刚隐藏的 beta，beta 的撤销状态发生变化。已增加换文件时的目的编辑器焦点交接，包含首次异步加载；仅文件变更触发，启动恢复与模式切换继续使用各自原有规则。如果用户已移到其他控件，取消晚到的焦点请求。隐藏编辑器的 beforeinput/keydown 明确阻止编辑事件。新增目标焦点、隐藏文件 historyUndo/Mod+Z、启动恢复和晚到初始化回归；初版原生结果不计为最终通过。

代价是最多保留 8 份阅读 DOM 和编辑器状态（原来 1 份）；不是任意文件大小下固定内存。首次打开、已淘汰文件、主题/路径等需要重建的情况仍有初始化成本。

## 分轮验证

轮 1 — 用例：三种文档规模的暖切换，以及两个文件分别编辑/保存/撤销。
  期望：无需重建，历史和保存目标相互隔离。
  实测：7 组新专项通过，6 次暖切换创建数为 0；实际保存内容精确一致，撤销只修改当前文件。
  结果：✅

轮 2 — 用例：空文件/CJK/emoji、源码替换后切回、比较标签与 HTML。
  期望：空文可编辑且撤销恢复空串；后台 flush 不覆盖新源码；非阅读文件保持惰性。
  实测：新专项通过，HTML 往返复用原实例，源码更改同步正确。
  结果：✅

轮 3 — 用例：9 个额外文件、连续快速切换、异步初始化期间切走、关闭活动文件。
  期望：最多 8 份阅读 DOM，淘汰后恢复历史，晚到初始化不能抢活动 bridge。
  实测：新专项通过；被淘汰旧 view 已 destroy，重新进入后仍可撤销到先前内容。

轮 4 — 用例：真实浏览器亮色宽窗与暗色720px，滚动、逐键abc、跨文件和模式往返。
