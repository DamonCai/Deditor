# 固定 Typora 清单：补齐与验收记录（2026-09-12）

本次执行沿用 [固定核对清单](markdown-typora-audit-2026-09-12.md)，排除导入、导出和字体类型。以下区分实际实现、已测范围与尚未闭环的边界；不以一批测试通过代表完整 Typora 等价。最新局部同步、复杂文档呈现对照和 macOS 普通输入复测已完成；下文剩余项仍未闭环。

## 实现与边界

| 原清单项目 | 已实施 | 仍有边界 |
| --- | --- | --- |
| P0 输入稳定性 | 初始化完成前禁止正文输入；组词、滚动及共同撤销保护保留 | macOS 测试中输入的是字母，没有激活真实候选窗口；Windows 未验收 |
| P0 长文资源 | 代码编辑器按进入编辑创建；脚注单块原文更新；未变脚注跳过 DOM 写入；当前文档的阅读编辑跨模式保留，隐藏时停止源码同步、释放命令入口，不拦截保存 | 首次解析和源码变化后的同步仍有开销；不是完整文档虚拟化；长文输入与真实 IME 的流畅度不能等同 |
| P1 查找替换 | 阅读模式大小写、全词、正则、单次/全部替换、捕获组、一次撤销；非法或零长度正则保护 | 按可编辑文本块查找，不跨块匹配；复杂保留块仍可切到源码编辑 |
| P1 链接 | Cmd/Ctrl 点击正文或保留块链接；本地文件与标题拆分；中文、重复标题、Windows/UNC、单次 URL 解码；预览使用同一标题 ID 规则 | 外部应用的真实打开行为受系统关联和平台影响 |
| P1 输入辅助 | 括号/引号配对、跳过闭合符、成对退格、选区 Markdown 包裹、表情前缀候选、键盘选择；组词时暂停 | 普通空选区的 Markdown 格式符仍使用原输入规则，未实现 Typora 全套自动配对偏好 |
| P1 历史与草稿 | Rust 独立历史目录、保存前后版本、草稿检查点、容量轮换；查看、恢复及作为新文档打开，恢复可撤销 | 不等于 macOS 系统 Versions；多进程同时写同一历史目录未验收 |
| P1 脚注布局 | 已引用定义集中在阅读文末，按引用顺序排列；不移动原文件中的定义字节；共享预览的脚注结构与样式 | 未引用定义在阅读文末保留，预览不显示；编辑状态的源码控件仍有自身布局 |
| P2 大纲 | 折叠、过滤、当前章节高亮、视口与光标同步 | 非完整工作区文档大纲系统 |
| P2 公式 | mhchem、显式标签、自动编号开关、label/ref/eqref；共用 KaTeX 渲染 | KaTeX 的命令覆盖不等于 MathJax/完整 LaTeX |
| P2 图表 | flowchart.js 流程图、js-sequence-diagrams 时序图，统一懒加载、取消与 SVG 清理；保留上游许可 | 图表编辑时仍保留原高度，离开源码后刷新图形；原生远程 PlantUML 依赖网络 |
| P2 代码块设置 | 行号、换行、缩进宽度、新建围栏默认语言；静态显示与编辑模式共用配置 | 默认语言只影响新建空代码块，导入源码不被改写 |
| P2 拼写 | 可启用系统 WebView 拼写检查 | 未实现独立词典、跨平台语言/忽略词管理；真实系统拼写菜单未验收 |
| P3 排版与嵌入 | Markdown 范围的自定义 CSS；拒绝全局字体和外部资源；HTTP(S) iframe 强制隔离沙箱 | 不是任意 Typora 主题兼容；需要额外权限的嵌入服务可能不可用，远程 iframe 全流程未验收 |

## 复杂文档和原文测试

- `tests/fixtures/markdown-typora-complete.md` 在原完整样例上加入化学公式、标签引用和 flow/sequence 等内容。保留 H1–H6、中英文、嵌套列表/引用/任务、表格、围栏、图片、HTML、YAML、提示块、脚注和长文。
- 浏览器使用真实 Preview 与阅读编辑并排对照，默认设置一轮 540 项检查 `differences: []`；该结果是已覆盖样例的样式和尺寸核对，不是任意 CSS 或任意文档的逐像素保证。模式复用和局部解析后再测仍为 540 项、`differences: []`，浏览器无错误。中文标题链接在 Preview 普通点击、阅读编辑 Cmd 点击后均跳至 H1（视口 top 分别为 143.09 / 167.09px）。
- 原文层新增交错脚注定义、CRLF、引用重排、连续单块编辑、跨定义分段/合段/插删、文末多定义追加及源偏移测试。阅读脚注移动只影响显示，不挪动原文。
- 输入框操作验证自定义正文颜色、代码换行和公式编号同时影响两侧，字体类型保持默认。任意 CSS 的选择器在编辑/静态 DOM 中可能存在语义范围差异，不能泛称全部一致。

## 长文性能与压力证据

样例：`?long&sections=500`，6303 行、152241 字符，新增 500 个表格。数据来自同机浏览器开发或生产验证页，存在并行构建负载；没有运行原版 Typora 同机对跑。

1. 脚注单块处理优化后，5 次按键到第二动画帧为 78.2、70.8、103.9、70.1、74.9 ms，中位数 74.9 ms；原生 input 对照 10.4 ms。文档 apply 约 3.9–6.2 ms，scrollToSelection 约 0.1–0.4 ms。它不是原生中文候选输入延迟，也不能因旧记录只有 3 次样本就声称快于旧中位数 70.5 ms。
2. 开发页反复切换曾两次出现浏览器 “This page crashed”，一次全新页面第二轮发生。新建生产页原旧实现连续三轮切换通过：阅读就绪加下一帧 3295.2、3242.5、3248.1 ms，原文完全一致。尚不能将开发页崩溃直接归因为单一产品原因。
3. 当前文档跨模式保留后，生产页连续六轮返回阅读为 570.4、598.7、581.2、581.7、567.4、574.4 ms；返回源码为 155.0、151.7、170.9、79.2、156.9、93.4 ms。原文不变，结束时只有 1 个 ProseMirror、1 个源码 CodeMirror，无浏览器错误。此时尚未优化源码变化后的同步。
4. 新增独立 500 表格 / 6 次完整创建销毁压力测试：全部销毁，原文一致；显式 GC 后堆内存 319、322、323、323、321、319 MB。此为 JSDOM 进程，不能替代原生/WebView 长期内存验收。
5. 早期 4.6–4.8 秒的源码同步测量实际把字符插在第 1 行，破坏 YAML 头，属于整篇结构变化；不能作为正文修改的基准。最终明确点击第 3,170 行正文，插入 `BODY_SYNC_CHECK`，保留 YAML：返回阅读 508.8 ms，其中 reset 5.2 ms、updateState 9.5 / 3.1 ms；撤销后 152241 字符原文完全一致。随后三轮返回阅读 368.4、393.8、387.4 ms；仍只有一个 ProseMirror 和一个源码 CodeMirror，无浏览器错误。
6. 源码更新先比较不变的首尾块，只替换变化的完整块，保留表格等未变控件 DOM。单行段落、标题和表格修改可局部解析；引用上下文、HTML、换行、代码/公式围栏和容器仍完整解析，避免改变围栏后吞并后文却误走快速分支。同源码 reset 仍支持强制重建，保护行内源码投影收起。

## macOS 原生实际验证

仅使用隔离应用 `DEditor Markdown Typora Review`，identifier `com.deditor.markdowntypora20260912`。自建样例位于 `/tmp/deditor-markdown-typora-native-20260912/fixtures/review.md`；未访问正式应用历史或用户原有文档。

- 原生应用打开完整样例，公式和图表正常呈现。
- 修改正文后保存；历史列表选择旧版本恢复、保存，磁盘内容与自建原始样例逐字节一致。
- 撤销恢复操作后保存得到修改版；重做后保存恢复原始版。
- 修改但关闭不保存后，在“恢复草稿”中找到刚才的内容，作为新文档打开，原文件保持原样；关闭自建文档并退出隔离应用，进程已确认退出。
- 尝试 Ctrl+Space / Ctrl+Alt+Space 后 `zhong` / `ni` 均作为字母输入，没有真实候选字窗口。系统设置只读检查显示存在简体拼音/搜狗输入法，菜单控制未成功；**不计真实 IME 通过**。
- 首次快速输入曾出现后续空格到 YAML 开头；后续同次调用、跨调用和截图后重复输入未稳定复现。随后增加初始化输入门禁；这不是已证明唯一根因。最新包完成后接口曾短暂捕获失败，再次选择应用后恢复。最新包连续输入、切源码输入、返回阅读、保存、两次撤销后保存均已复测：磁盘文件与自建完整原始样例逐字节一致；关闭测试文件并退出应用。
- 原生工具 `typeText` 对 `_` 的输入在阅读和源码两侧均未送入文档（`FINAL_NATIVE_CHECK` 实际为 `FINALNATIVECHECK`），因此此次验收按实际送入字符核对位置、模式同步和撤销，不能把工具省略字符作为 Markdown 模式独有缺陷，也不能据此验收符号键输入。
