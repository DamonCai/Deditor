# 表格内 Enter 换行修复（2026-09-14）

## 范围和原因

用户反馈阅读编辑的表格内按 Enter 后光标直接跳到表格外。本次仅调整表格键盘行为。

Milkdown GFM 的 ExitTable 同时绑定普通 Enter 和 Mod-Enter；现有表格测试把该行为列为通过项。用 Git 原版 `tableKeys.ts` 隔离替换、运行新回归，确认按 Enter 后选区深度为 1（表外段落），而预期为 4（单元格段落）。原始尝试在测试运行期间修改源码，日志混合了两个版本，不能用作前后证据；有效失败对照是 `before-isolated.log`。

`handleTableKeys` 现优先处理普通 Enter：在当前单元格插入 hardbreak，由已有保真序列化层写为 `<br>`，连续 Enter 保留连续换行。单元格矩形选区的 Enter 转入目标格编辑，不清空内容。Ctrl+Enter（Windows/Linux）及 Cmd+Enter（macOS）仍可退出表格；Shift+Enter 保持原行为。输入法组合期间不执行新增处理。

## 不同轮次验证

轮 1 — 用例：普通单元格中间 Enter，继续输入并撤销。
  期望：光标仍在当前格，前后文本被换行分开，相邻格不变。
  实测：旧实现新回归失败 `1 !== 4`；修复后通过。真实浏览器逐键将 `one` 改为 `o<br>xne`，两次撤销恢复完整原文。
  结果：✅

  实测：24 组表格专项全部通过，包含新边界及矩形选区。模拟 compositionstart/Enter/compositionend 不修改原文；这不代表真实中文候选验收。
  结果：✅

轮 3 — 用例：暗色 720px 内容区，列表连续 Enter 后逐键输入；末格 Enter 后 Tab；Cmd+Enter 后续写。
  期望：列表文字留在原格，Tab 创建一行，显式退出后在表外输入。
  实测：浏览器列表 `alpha` 后两次回车及 `tail` 留在同一格；末格 `four<br>` 后 Tab 只新增一行并写入 `n`；Cmd+Enter 后 `out` 出现在表外。截图检查换行显示正常。
  结果：✅

轮 4 — 用例：相邻操作与共享历史回归。

  实测：8 组连续表格操作、8 组 Enter 历史、107 阅读集成、145 通用与 8 分隔线通过；生产构建通过。连续操作中两处原测试也以 Enter 退出，已更新为 Ctrl+Enter 再通过。
  结果：✅
