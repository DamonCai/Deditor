# Markdown 预览性能实施与剩余项目（2026-09-12）

用户授权“按照建议先调整，然后看还剩哪些要优化”。本轮锁定三项：未改代码围栏高亮缓存、Mermaid 过期队列跳过、双向滚动位置索引。两个 agent 分别实施前两项，主任务实施滚动并整合验证；随后独立复查索引失效边界。没有扩展修改阅读输入、历史、HTML 或 XMind，也未提交推送。

工作区存在并行基本编辑/跨块/保存修复。新增性能脚本接入 `perf:markdown-preview`，并纳入 `perf:all`；保留并行任务对 package 和其他文件的改动。本轮不是整套 Markdown/Typora 验收完成声明。

## 实施结果

- `src/lib/markdownHighlightCache.ts` / `markdown.ts`：普通代码围栏按精确内容、实际加载语言、Shiki 主题缓存。进程内 LRU 上限 256 项、8 MiB UTF-16 键与 HTML 负载（对象开销另计），超大条目跳过；行号按当前源码重新附加。仍先检查语言，加载恢复不会被旧纯文本结果遮蔽；高亮异常的回退结果不缓存。保留一个显示用终止换行规则和真正的尾部空行。
- `src/lib/mermaidHydrate.ts`：进入串行队列及等待依赖加载后检查取消状态，尚未开始的旧任务直接跳过。有效任务仍按原顺序初始化主题/导出配置、渲染及绑定；已经开始的 Mermaid 渲染仍等待完成后丢弃过期输出。没有加入 SVG 缓存。
- `src/lib/previewScrollIndex.ts` / `Preview.tsx`：双向同步共享标记位置表，有序值二分查询，嵌套/定位 HTML 非单调值按原来的“首个大于目标即停止”规则回退。保持插值、首行和贴底哨兵不变。HTML 更换、图片/图表、字号/主题/自定义样式、窗口及块大小、字体加载、悬浮/焦点/表单状态均能失效；CSS 动画期间重新测量。隐藏后清空保留标记，卸载清理观察器和事件。目录滚动高亮不触发正文重测。

## BEFORE / AFTER / DELTA

同一台机器、相同固定样例与工具，各五轮取中位数。下列是局部工作测量，不是整页输入或模式切换时间。

| 指标与方法 | BEFORE | AFTER | DELTA 与代价 |
| --- | ---: | ---: | --- |
| `renderMarkdown`，65,606 字符、100 个不同 TypeScript 围栏，每块 20 行；预热后只改末尾正文 | 169.207 ms；每轮高亮 100 次 | 0.983 ms；每轮高亮 0 次 | -168.224 ms / -99.42%；增加有上限的内存缓存，超过缓存工作集会淘汰，首次/全部改动仍需高亮 |
| Mermaid 受控队列：2 个有效 + 100 个排队后取消的任务 | 每轮 render 102 次，其中过期 100 次 | 每轮 render 2 次，其中过期 0 次 | 总调用 -98.04%，过期工作 -100%；不增加 SVG 缓存，不取消已经运行的渲染 |
| 真实浏览器 Preview，1,002 个标记，几何不变时 100 次读取/查找一组、共五组 | 每次均值的中位数 0.631 ms | 约 0.001 ms（低于 0.01 ms） | 约 -0.630 ms / -99.8%；四次实际滚动帧全文标记扫描均为 0。增加 O(n) 标记表和 ResizeObserver 目标，首次/布局改变仍需完整测量 |
| 固定同一源码快照的生产入口 JS，仅替换三个优化前文件做基线 | 1,961,920 bytes | 1,966,923 bytes | +5,003 bytes / +0.255%；gzip 621,090 → 622,328 bytes（+1,238） |

浏览器计时分辨率有限，约 0.001 ms 是批量调用均值，不能解释为单次达到微秒级精度。基线读取函数与原实现相同，包括查询、每个 offsetTop 和线性查找；新路径包含观察器待处理记录、容器尺寸检查与缓存查询。页面整体布局/绘制不包含在这个数字中。

高亮原始五轮：BEFORE `[167.552,171.296,205.823,169.207,167.810]`；AFTER `[1.791,0.972,0.878,0.989,0.983]` ms。每轮 HTML 均做逐字一致性检查。完整 `perf:all` 中独立重跑缓存后中位数为 1.119 ms，所有高亮调用仍为 0。

滚动 JSDOM 补充测试覆盖 0/1/30/2000 个标记及 72,150 个边界查询。整套运行中 2000 标记基线 2.367 ms、缓存后约 0.00033 ms；这是 DOM 接口微基准，不替代上面的真实浏览器检查。`perf:react`、资源 soak 及其他既有性能套件均通过，本轮没有新增 React 状态更新或减少 React 渲染次数的承诺。

## 五轮不同维度的验证

### 轮 1 — 基础与输出保真

期望：只跳过重复工作，代码 HTML、源码位置和图表有效任务顺序一致。

实测：高亮缓存四组专项通过，修改单块只高亮该块，移动围栏仍更新 data-line；有效 Mermaid 多块及重复 hydrate 不增加副作用。源码/预览代码块 32 项空行与主题回归通过。结果：通过。

### 轮 2 — 边界和容量

期望：空文档、重复/无序标记、Unicode、尾部空行、语言/主题隔离、缓存淘汰均安全。

实测：72,150 个查询与原线性规则逐个相等，0/1/30/2000 标记测试通过；LRU 项数/负载预算、超大条目不驱逐其他内容、主题和语言切换、纯文本回退后语法恢复通过。结果：通过。

### 轮 3 — 真实浏览器交互组合

期望：实时预览双向滚动不偏移，内容尺寸变化后重新测量，恢复隐藏 DOM 不用旧节点。

实测：自建页面 `tests/markdown-preview-performance-review.html`，1,002 标记、真实 Mermaid SVG，完成输入行号的首/中/尾定位、实际预览滚动回传、720px 宽、18px/紧凑/代码换行、暗色、异步图片、同任务内自定义 CSS、块间位置重新分配、正文修改恢复、冷 DOM 释放恢复。原文一致。真实指针移入并点击自定义样式列表，所有块尺寸不变时标记顶部 39 → 59 px，缓存立即匹配新位置。结果：通过。

独立审查发现 hover/focus 改 padding 且保持总高度时，只有 MutationObserver/ResizeObserver 仍会漏失效，已补输入状态及动画事件后完成上述复测。第一次自动点击时 hover 让目标移动 20px，落点未命中；重新定位点击后结果通过，未将未命中的第一次点击当产品事件失败。

### 轮 4 — 取消和错误路径

期望：废弃任务不执行；有效任务错误处理、清理和后续队列可恢复。

## 还剩什么，建议下一步顺序

后续更新：重复源码坐标查询、历史差异扫描和后台预览生成已进一步优化，见 [输入与后台性能实施](markdown-input-performance-2026-09-12.md)。以下是本篇完成时的排序，首次坐标查找、AST 偏移及跨模式缓存等未被这次后续实施全部解决。

1. **长文输入：重复源码坐标和历史差异计算。** `MarkdownVisualEditor.tsx` 对空选区仍重复算 anchor/head，修改前后和发布位置叠加；`markdownVisual/document.ts` 的 sourceOffset 仍遍历顶层块。先去掉相同位置的重复计算，再把已知修改范围传给 `markdownSession.ts`，避免再次从全文首尾比较。需专项保护选区、原文、组词及跨模式撤销。
2. **隐藏预览与跨模式重复生成。** `Preview.tsx` 渲染 effect 尚不受 active/retainDom 控制，后台源文/主题改变仍生成 HTML；离开预览时 `App.tsx` 卸载 PreviewHost，回来仍重新生成。可以有限缓存文档版本的 HTML，隐藏时标记过期、激活前更新。已有 DOM 数量上限要保留。
3. **长文 AST 偏移与定义上下文。** `markdownVisual/document.ts` 的局部修改虽已有快路径，后续树的绝对偏移仍复制，脚注定义上下文仍会拼接。评估块内相对位置或延迟偏移前，先分别测定义密集、嵌套、表格样例。不要误报所有脚注文档每次都完整重投影。
4. **模式/主题和大 DOM 显示。** 同标签阅读实例已跨模式保留；主题/语言/路径仍使初始化 effect 重建。需要把显示大 DOM、静态块挂载、主题重建分别计时。旧诊断约 485ms 是旧开发页单次模式样例，不是本轮实测或归因结论。
5. **标题、大纲、搜索与未变图表复用。** 标题缓存按整个文档，正文改动后仍遍历；大纲/搜索打开时可更细地映射未变块。关闭时已停止计算，不重复列作缺失。Mermaid 本轮仅跳过过期任务，未变 SVG 复用仍需独立解决 ID、绑定和主题/导出隔离。

这些剩余项经当前代码复核，收益还需各自固定范围并测量，没有在本轮继续修改。
