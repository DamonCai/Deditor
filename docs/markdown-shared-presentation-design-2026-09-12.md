# Markdown 共享展示层评估（2026-09-12）

用户明确要求阅读编辑与实时预览保持一致，希望通过共用前端显示组件减少反复比对。本记录前半部分保留最初的设计依据；用户随后明确要求实施，共享展示层现已接入，详见下方实施记录。

## 当前情况

- `src/preview.css` 已同时服务 Preview 与 `.ProseMirror.md-document`，字体、字号、标题、正文、颜色及多数块样式共用。
- `Preview.tsx` 使用 markdown-it 输出整篇 HTML；`MarkdownVisualEditor.tsx` 使用 ProseMirror schema/NodeView 创建可编辑 DOM。表格、列表、图片等有不同的包裹结构，`markdown-visual.css` 因而仍需要适配规则。
- 代码、公式和图表已经复用 Markdown 渲染逻辑；图片路径规则和脚注浮层也已共享，但 HTML 挂载、清理及异步渲染生命周期仍分散在 Preview、codeView 和 rawView。
- 阅读编辑与“只读”已经共用同一个编辑组件。将实时预览也替换成只读编辑器在结构上可行，但会为预览引入整套编辑器与节点视图，并改变源码行定位、文末脚注布局等既有行为，需要独立评估性能和兼容性，不能仅作为省去 CSS 对照的捷径。

## 推荐方向

采用共享展示层与两种宿主适配，逐步收敛，而不是先大改编辑器或把同一内容交给 React 与 ProseMirror 同时管理。

1. **统一文档显示配置**：字体、字号缩放、主题、密度、正文宽度与内边距由单一模块提供；可提供共享 `MarkdownDocumentSurface` 外壳与对应 DOM 适配。宿主不再各自计算和声明正文排版。
2. **统一静态块渲染**：代码、公式、图表、保留 HTML、图片及脚注浮层共用渲染/挂载/清理入口，保留异步结果过期校验、图片根目录更新与编辑时占位高度。React 预览和 ProseMirror NodeView 都调用该入口。
3. **统一可编辑块的显示结构约定**：标题、段落、引用、提示块、列表、任务、表格与图片使用相同的语义结构及类名。ProseMirror 负责内容 DOM 和光标，React 不重建正在编辑的正文；编辑专用 CSS 只保留控件、光标提示、选择态及必要包裹适配。
4. **用自动化守住边界**：完整自建 Markdown 在同宽、同字号、同主题下自动检查关键块的字体、颜色、行高、间距和尺寸；覆盖亮暗、窄窗、聚焦/失焦、原文不变及滚动。结构差异有明确原因，例如脚注编辑位置与预览文末布局，不能用整页截图相等掩盖。浏览器几何检查与输入/保存/撤销回归仍需保留。

实施顺序先统一文档配置与静态块生命周期，再收敛列表/表格/图片包裹。不要为了共用一个 JSX 组件逐字替换整篇 HTML，否则可能重新引入中文组词、光标、撤销和滚动问题。保护源码滚动联动、HTML、XMind 和现有文档保真行为；不扩展导出需求，不提交推送。

预期效果是新增和修正排版只改一个来源，减少两套样式漂移；共用显示组件不能替代必要的编辑交互和自动化验收。


## 已实施与验证

2026-09-12 已实施共享外壳、静态渲染生命周期与正文排版参数，具体改动、复杂文档对照和仍未验收的原生边界见 [共享展示实施与验证](markdown-shared-presentation-verification-2026-09-12.md)。

- `MarkdownDocumentSurface` 被 Preview 与阅读编辑共同使用，统一字号缩放和文章主题。阅读编辑的内容 DOM 仍由 ProseMirror 管理。
- `markdownDisplayHtml` 与 `hydrateMarkdownDisplay` 被 Preview、代码/图表 NodeView、保留块 NodeView 共同使用，统一 HTML 处理、图表元数据保留、图片处理和取消生命周期。脚注浮层继续使用此前共用的安装函数，复用已经渲染的内容。
- `preview.css` 是字体、宽度、间距及静态块样式的单一来源；编辑器 CSS 消费共享参数，保留光标提示、源码区和编辑控件。
- 已实测修复表格隔行色错位、窄窗代码块额外换行、嵌套列表累积间距。没有把只读编辑器整个加载到实时预览中，没有重建输入中的正文。
