# 格式符批量输入紧急核查（2026-09-22）

基线：`735e731`。本次只修改 `src/lib/markdownVisual/inputAssist.ts` 和格式符专项，不改变输入法、Markdown 语法、源码投影或偏好。

## 已证明的缺口

真实 Visual 组件先输入 `Pair testing paragraph. **native`（末尾两个星号由配对生成），再在同一 DOM observer 批次执行两次浏览器文本编辑：每次派发 `beforeinput/input`、`inputType=insertText`、`data="*"`，并修改 DOM 文本及原生选区。由 ProseMirror 自己读取 DOM、计算差异，而非直接调用 `handleTextInput`。

修改前，ProseMirror 将两次编辑合并为一次 `handleTextInput(from=34,to=34,text="**")`；原有 `text.length !== 1` 守卫拒绝处理，最终源文精确为：

```text
Pair testing paragraph. **native****\n
```

这与此前额外两个星号的形状相同，但**不能证明它就是此前原生首次观察的原因**。上轮四次原生 Trace 的 99 次输入全部为单字符、非 composition；未捕获异常当次事件。本次不把原生未定因项冒充已定位。

## 修复范围

仅在当前存在自动生成配对、已观察到多个非 composition 的 `beforeinput: insertText`，且这些事件与 ProseMirror 合并后的文本、范围、原文档和当前选区完全一致时，按已观察事件的顺序调用既有输入处理。这样两个闭合符分别跳过，而正文、转义和重复开符继续沿用原逻辑。

这层记录不取消原生事件。不凭多字符字符串猜测闭合意图：粘贴、拖放、组合输入、关闭自动配对、缺少或无法匹配输入事件的多字符文本仍原样输入。发生组合输入、指针操作、文档或选区改变时放弃旧记录。不会引入文件大小或正文长度限制。
