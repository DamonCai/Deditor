# Markdown 标题级别累加修复

日期：2026-09-11。用户反馈只输入一个 `# `，结果变成 `##### `。

## 复现与原因

在浏览器自建样例中，把现有标题设置为 H4，光标放在标题开头，输入一个 `#` 再输入空格。修复前工具条显示 H5，保存源文为 `##### 阅读时自然编辑`，与用户反馈一致。

Milkdown 上游的 `wrapInHeadingInputRule` 在已有标题内采用“当前级别 + 本次井号数”，并将结果限制到 6。这是输入转换规则的问题，不能用无修改打开/保存的保真测试来证明它没有问题。

## 修改

在 Markdown 可视编辑器初始化时移除累加规则，安装独立的绝对级别规则：段首一至六个 `#` 加空格，分别设置 H1–H6，与当前标题级别无关。重复输入相同前缀不再加级；超过六个井号、行中井号和代码块内容不触发标题转换。源码编辑路径和其他文件类型不改动。

## 验证

1. **原问题复验**：H4 行首输入 `# `，源文为 `# 阅读时自然编辑`，工具条为 H1；不会变为 H5。
2. **级别矩阵**：原正文/H1–H6 × 输入一至六个井号，共 42 种组合，用真实编辑器插件的输入处理链逐字输入。每种组合检查实际节点级别和最终源文，再重复同一前缀，确认不累加。
3. **空行与边界**：空文档、空行及空 H1/H4/H6 后输入 `# ` 再输入正文，均为一级标题；七个井号、行中井号、代码块井号保持文字。浏览器也实际从普通段落回车、新空行输入 `# ` 和“新标题”，源文仅有一个井号。
4. **模式与历史**：浏览器在现有 H4 文档中执行转换、撤销、重做，分别得到 H1、H4、H1；重复输入一级前缀保持 H1。使用自建样例，不读取用户已有文档。
