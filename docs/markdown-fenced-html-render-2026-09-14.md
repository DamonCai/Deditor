# Markdown HTML 围栏渲染修复（2026-09-14）

## 范围与复现

用户先反馈从富文本复制后形成的拆分/转义 HTML 围栏在实时预览和阅读编辑中没有形成代码块，随后提供 `/Users/damon/Documents/fy_report/测试.md`。该文件是标准 ` ```html ` 围栏，正文为使用 CSS 自定义颜色变量的内联 SVG。修复前标准围栏只按 HTML 源码高亮，不会生成 SVG；拆分围栏还会被 Markdown 解析器当成普通段落。

本轮只处理 Markdown HTML 围栏的识别、展示、编辑和原文保真。测试使用自建页面和逐字节副本。用户随后把文件扩展为 61 个换行、5,865 字节的完整 SVG；本轮最终基线 SHA-256 为 `7d18e61528d9cbadc950615523cb0404bd057b2683bb945d8cbf9f0e5f10401d`。旧隔离包原生验证时曾自动保存 6 个测试产生的文末空行，发现后立即用进入原生验证前的逐字节副本恢复；最终用户文件与副本哈希、字节内容完全一致。

## 实施

- 新增 `src/lib/markdownFence.ts`，兼容 `` ``` ` ```html `` 与带反斜杠的同类围栏。归一结果保持字符串长度和行数不变，视觉文档的源码位置仍对应原文；保存继续使用原始围栏。
- 实时预览和阅读编辑共用归一后的 Markdown 解析入口，避免两种模式结果不同。
- `html` 围栏输出惰性占位，由 `markdownDisplayHtml` 读取源码并通过 DOMPurify 清理后生成实际 HTML/SVG。`script`、事件属性和不安全 iframe 不会进入展示 DOM。
- HTML 展示块限制在正文宽度内，SVG 保持 `viewBox` 比例。完整文件实际使用 28 个 Tailwind 风格颜色变量，覆盖 `slate / indigo / emerald / sky / rose / amber`；这些变量现全部提供标准色值，避免无效的 SVG `fill` 回退为黑色。
- 后续复核发现黑色还有第二个来源：样例左侧矩形明确使用 `fill="none"`，在暗色主题下会透出应用的深色页面。围栏 HTML 的 SVG 现使用白色默认画布；SVG 自己绘制的背景仍可覆盖它，透明模块不会再随应用主题变黑。
- 用户样例的 SVG 声明 `viewBox="0 0 680 360"`，实际图形只占 `y=176..250`，约 79% 的纵向画布为空。新增 `src/lib/htmlBlockHydrate.ts`：围栏 HTML 中只有 `width="100%"`、带 `viewBox` 且没有显式 `height` 的响应式 SVG 会在挂载后读取实际图形边界；当某个轴的内容不足原画布 85% 时，展示 DOM 对该轴增加小幅留白后收紧。显式高度和内容已占满画布的 SVG 保持原样，Markdown 源码不改。
- 阅读编辑中单击渲染结果仍可进入既有 CodeMirror HTML 源码编辑，编辑、撤销、重做和重新挂载保持 Markdown 原文结构。
- 阅读编辑的模式/标签焦点恢复不再把记忆在 HTML 围栏内部的光标误当成用户点击。首次进入阅读编辑、从源码切入，以及从其他文件切回时先显示渲染结果；只有实际点击渲染块或键盘进入才展开源码。
- 纯 HTML、Mermaid、PlantUML 和旧式图表围栏不再初始化 Shiki；只有普通代码围栏才加载高亮引擎。HTML SVG 已经挂载到页面时同步完成边界计算，避免额外等待一个动画帧；离屏代码块的 staging DOM 仍延后到挂载后计算，保持正确尺寸。
