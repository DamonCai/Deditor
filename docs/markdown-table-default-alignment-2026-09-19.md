# 默认新增列不再自动写入左对齐标记（2026-09-19）

用户指出：工具栏新建表格生成无冒号分隔行，表格内手动加列却生成 `:--`。两者都是有效语法，但创建入口的默认对齐值不一致。

工具栏插入 Markdown 的列对齐值为 `null`；Milkdown 单元格 schema 的默认值为 `left`，表格内加列使用默认属性，因此序列化自动带入冒号。本次在已有单元格及表头 schema 扩展中统一默认值为 `null`。显示仍默认靠左；原文已有显式左、中、右对齐和主动设置对齐的行为保持。横线长度仍由已有序列化器按列宽生成，不全局格式化旧文档，也不删除用户原文中的冒号。

轮 1 — 用例：无对齐表格首列前、中间及末列后加列。
  期望：新列默认值与工具栏建表一致，分隔行不额外生成冒号。
  实测：修复前新增断言失败，实际 `left`、期望 `null`；修复后三处加列、保存、撤销重做及重新挂载通过。
  结果：通过。

轮 2 — 用例：已有左/中/右对齐的表格插入默认列，再将新列分别设置为左/中/右对齐。
  期望：已有对齐不变，新列初始不带冒号，主动对齐能保存重开。
  实测：28 组表格专项通过；含此前围栏输入保真、表格换行、增删和格式回归。
  结果：通过。

轮 3 — 用例：真实浏览器通过列边界出现的“添加列”按钮操作。
  期望：普通表格新增列不带冒号；混合对齐表中插入列保持周边对齐，撤销及重新解析正确。
  实测：默认表格实际点击后新增列分隔符为无冒号横线，撤销精确恢复原文；混合表新增列后显示对齐依次为 left/center/left/right，源文依次为显式左/居中/默认/显式右，重新解析正常。
  结果：通过。使用自建测试页，未读取用户文件。
