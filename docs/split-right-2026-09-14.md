# Split Right：左右独立标签组（2026-09-14）

## 范围与用法

用户确认首版：左右两个面板、标签右键“向右分屏”、拖动调整宽度、关闭时合并标签。

- 标签右键“向右分屏 / Split Right”，或标签条分屏图标；现有 `Cmd/Ctrl+\` 切换分屏。
- 左右各自保留标签、当前文件、Markdown/HTML 显示模式、光标及滚动位置。新打开的文件进入当前面板。
- 同一个文件保留一份正文、保存状态和历史，两侧实时同步。普通文本继续使用 CodeMirror 历史；Markdown 沿用共享保真会话；XMind 沿用档案与编辑历史。
- 保存、撤销、查找、工具栏动作跟随面板焦点。鼠标按下、键盘聚焦、普通 click 和辅助功能点击均进入面板激活路径。
- 同文件重复标签关闭时只移除该侧视图，最后一个视图关闭时才走原有未保存确认。关闭分屏合并所有标签，不丢弃右侧独有文件与未保存内容。
- 分隔线可拖动；键盘左右方向键调整，Home 或双击恢复等宽。
- 本版限左右两组，不做嵌套分屏或跨组拖放。与此前分屏开关一致，不持久化分屏布局；文档仍通过既有会话恢复。

## 实现

`EditorGroups` 管理两组布局；`EditorPane` 复用原 App 的完整编辑/预览区域。Zustand 保留全局活动命令接口，在面板内提供各自的标签和模式投影；文档始终共享，避免复制文件对象导致双份脏状态。两侧 CodeMirror 缓存和 Markdown 位置分别保存，发布活动 bridge 时校验具体视图拥有者。多个文档 flush 注册可共存，后台视图不提交旧正文。

新增 `textHistory.ts` 保存每份普通文本的 CodeMirror 历史；保留已有按键分组，在另一侧撤销/重做时将结果同步到各视图。XMind 共享已发布的会话版本，分别保留画布选择与相机；没有修改其布局或专用控件样式。

本次没有提交、推送或替换已安装的正式应用。保护了同时进行的列表、搜索和预览改动。

## macOS 原生验收

使用唯一应用标识 `com.deditor.splitreview20260914` 和自行创建的 alpha.md / beta.md / plain.txt。正式应用与用户文档未改。

初版控制曾出现保存快捷键变为字面 s、菜单元素失效及截图不可用；未把该快捷键尝试计为通过。已归档当时保存的自建文本，并退出测试进程。重启最终包后菜单恢复可操作。

最终含 click/contextmenu 焦点修正的独立包完成以下闭环：

- 右侧 Alpha 文末逐键输入 a/b/c 并通过原生 File → Save 保存。
- 左侧切 Beta 逐键输入 x/y/z，不保存；直接辅助功能点击右侧 Undo，Alpha 恢复原文、Beta 仍保留 xyz。此时原生保存只写 Alpha；三份磁盘文件逐字节等于初始副本（Beta 的未保存内容未误写）。
- 重新激活左侧后直接点击右侧 Redo，再保存：Alpha 精确增加 abc，Beta 磁盘仍保持初始内容。随后激活左侧保存，Beta 精确增加 xyz。
- 合并后关闭所有测试文件，从自建目录重新打开 Alpha，再向右分屏并打开 Beta；两边显示已保存的 abc / xyz。原生截图确认标签、工具栏、正文布局正常。
- 关闭 Beta、关闭右侧 Alpha 后自动收起分屏，再关闭左侧 Alpha，使用应用菜单正常退出。进程检查确认测试实例已退出；自建浏览器标签和两个测试服务也已关闭。

精确校验记录为 `native/final-click-undo-save.json`、`native/final-click-redo-save.json`、`native/final-native-reopen.json`。测试包路径为证据目录下的 `DEditor Split Review.app`。Windows、真实 IME 与原生分屏快捷键尚未新增通过结论。
