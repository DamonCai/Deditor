# Markdown 编辑范围与跳页修复

日期：2026-09-11。用户反馈上部可编辑、下部不能编辑，输入时还会跳到页面下方。此前自动化通过未覆盖这组实际操作，不能用旧测试结果否定该问题。

## 已复现的错误

1. 搜索文末文字，关闭搜索，回到标题输入 A：旧实现立即选中文末搜索结果并滚动过去；接着输入 B，会覆盖文末原文字。浏览器实际记录到选区为“最后”，标题只有 A，尾段变为“B一段保留三空格”。原因是搜索副作用依赖每次文档更新，并且不判断搜索是否关闭，每次都执行选中首个结果和滚动。
2. 含引用式链接、键帽 HTML 或颜色 span、`<br>` 的列表，原先整组被转换成保留源码块。页面呈现得像普通内容，但无法直接输入；表格也可能受同一判断影响。
3. 保留源码块和代码块缺少完整的内外选区同步，保留块还会在输入时重新呈现预览，容易让编辑位置、工具条和视图不一致。

## 修复

- 搜索结果可随文档更新重新计算，但只有打开搜索、修改查询及上/下一个操作能够主动移动选区；正常输入不再重新定位。关闭搜索后保留查询也不会影响编辑。
- 引用链接使用可编辑 link 标记，保留引用身份；修改折叠/快捷引用的显示文字时，必要时转换为完整引用，避免链接失效。引用式图片也不再阻止周围正文输入。
- 常见行内 HTML 与 `<br>` 转为可编辑标记/换行，保留原文拼写。HTML 源属性不直接注入页面，实际 DOM 只使用允许的行内标签和少量呈现样式。
- 更新保真文档层的局部重解析：带上现有引用定义，避免连续编辑后引用上下文丢失而重排整个列表。
- 点击特殊保留块可就地打开源码；编辑时隐藏预览并暂停重绘，确认/退出后显示最新结果。源码块与代码块的光标、选区同步到父编辑器；只读还会阻止块内撤销事件修改文档。

## 四组验证

### 1. 故障复现与搜索修复

期望：搜索过文末内容后，在顶部连续输入不会移动光标或改写尾段。

实测：修复前已复现覆盖；修复后在自建长文中输入“甲”“乙”，标题为“长文编辑回归甲乙”，文末“搜索定位目标。”不变，滚动位置始终为 0。搜索保持打开时，回到顶部连续输入也保持原位置。集成测试同时验证搜索开启/关闭两个状态。

结果：所列浏览器操作与回归通过。

### 2. 上下区域与语法组合

期望：含引用、HTML 和换行的列表/表格可直接修改，未修改源文保持原样。

实测：自建 30 章节长文里，下方列表、引用表格单元格及最下方正文均直接输入成功；底部正文编辑前后滚动位置均为 3486。模型测试覆盖完整、折叠、快捷引用改名与重新打开，引用图片、键帽、RGB 颜色和 `<br>` 周边文本编辑；连续修改引用列表保留原列表符号及定义。

结果：所列组合通过；未识别复杂 HTML 仍通过就地源码编辑，不能声称任意 HTML 都是富文本编辑。

### 3. 特殊块、历史与只读

期望：特殊块可点击编辑，输入不跳到其他段；源码/可视化撤销一致，只读不接受修改。

实测：点击 `<custom>` 呈现内容打开内部源码，连续输入“更新”“完成”，得到 `<custom>更新完成特殊块原文</custom>`，输入前后滚动位置均为 3612，文末未被修改。确认后返回最新预览，Esc 退出也复验。代码块编辑后切源码再编辑，两次撤销分别恢复源码与代码修改，保留更早正文输入。只读页面全部可见 contenteditable 为 false；集成测试确认块内快捷键与原生历史事件均不能修改文本。

结果：所列操作通过。自动化历史事件不是系统原生菜单的完整验收证据。

### 4. 布局与完整回归

期望：主题、窄窗口和其他文件能力不被修复影响。

实测：亮色和深色浏览器页面已检查，720×900 下工具条换行、引用列表和表格正常，页面 clientWidth/scrollWidth 均为 720。独立暂存区快照执行生产构建及 `npm run test:all`，包含 HTML、文件保存、XMind、导出、语法和图标原有回归；没有混入同时进行的 XMind 未提交代码。

最终自动化：28 项 Markdown 文档测试、16 项集成测试（运行时异常为空）、117 项通用回归、70 项 XMind、12 项导出通过；语言高亮与文件图标套件通过，TypeScript/生产构建通过。2000 段文档层性能仅作观察值，不代表原生完整页面延迟。React DOM 在测试环境创建 DOM 后再加载，保证输入事件使用正确实现，避免测试误走旧浏览器兼容路径。

原生构建：独立快照执行 `npx tauri build --config tests/markdown-native-review.conf.json --bundles app` 成功。原生控制器本轮能连接旧隔离进程，但窗口仅显示空白；退出旧进程、启动最新构建后，获取窗口内容两次失败（无法完成/超时）。因此真实 IME、原生保存及系统菜单交互仍未计为通过，Windows 也未验收。这里仅记录工具所见，不能据此判定最终应用必然白屏或兼容性已通过。
