# 表格内公式后中文输入修复（2026-10-07）

用户提供的 `问题.md` 中，人名使用 `$\color{#0089FF}{...}$` 渲染，紧接 `<br>`。对应阅读编辑模型是 `math_inline` 与 `hardbreak` 相邻。

## 原因与修复

Milkdown 的 `inlineNodesCursorPlugin` 在两个行内非文本节点之间插入两个可编辑 widget。它拦截普通 `beforeinput`，并在组合输入开始时加锁；`compositionend` 返回 `true`，使 ProseMirror 自身的组合结束处理无法运行。其延迟提交仅在光标仍处于相邻节点之间时执行，无法可靠处理原生预编辑产生的 DOM 和选区。

使用真实阅读组件和 DOMObserver 复现：在该边界发送组合开始、预编辑、中文提交和组合结束后，原代码的 `view.composing` 仍为 `true`。移除这一个插件后，同一流程结束为 `false`，文字与光标留在人名后。保留 ProseMirror 原生输入与选区处理，不添加输入法文字过滤、强制提交或额外源码字符。

## 原生补充定位

第一版仅移除插件的普通隔离包中，第二行行首向左跨过换行后，逐键 `n`、`i`、空格可在人名后提交“你”。但鼠标点击公式右侧同一行空白，WebKit 将位置解析到公式左侧（状态栏 Col 21），输入出现在人名前；该问题不能算首版已修复。

追加修复限定在行内原子节点紧接换行的边界：当浏览器给出原子节点左侧位置，但实际点击坐标在该节点可见右边缘之外、且仍在同一行高度内，将光标放在节点后。点击公式内部、下一行、Shift 扩选、只读和组合输入继续走既有逻辑。M09 覆盖几何回退、随后中文输入和不应干预的分支。末次修改重新运行 9 组专项、4 组行内导航及 11 组日常输入，并重建生产和隔离 macOS 包。

隔离配置使用 `com.deditor.mathreview20261007`，明确设置 `bundle.fileAssociations: []`；生成的 Info.plist 无 CFBundleDocumentTypes。没有替换日常安装应用。
