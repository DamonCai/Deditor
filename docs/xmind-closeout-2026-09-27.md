# XMind 原版视觉与当前待办清理（2026-09-27）

本轮只使用仓库生成的样例，对照本机原版 XMind 与 DEditor 浏览器实际组件。完成 XM-01 的具体形状/主题组合对照及确定差异修复，补齐 XM-02/03 的原版证据；不宣称所有字体、主题或平台像素完全一致。

## 原版对照与修复

| 样例 | 原版与 DEditor 观察 | 处理 |
| --- | --- | --- |
| 无 theme、根无填充、显式 `fo:color=#ffffff` | 原版白底上的根标题同样不可见，AX 仍有完整标题；DEditor 同样保留白字 | XM-02 完成；不擅自把明确白色改黑 |
| Smart light / Smart dark | 每表 7 个主题，含根、浅填充、灰色、半透明、无填充、显式粉色及深填充，另有边界/联系 | 两表自动文字颜色实际一致，XM-03 按这两套待查主题完成 |
| 亮/暗四形状复合内容 | 圆角矩形、胶囊、紧凑圆、菱形；中文+英文双行、130×70 图片、优先级标记、标签 | 逐组合截图；固定圆角半径 8 已与原版声明一致，无需修改 |
| Canonical `customWidth` 未设置 / 150 / 300 | 原版胶囊和菱形忽略主题宽度；此前 DEditor 错误地据此折行 | 两形状按内容排版；格式面板禁用宽度输入并说明原因，形状改变及撤销同步恢复可用状态；原文件属性保留 |
| 同上，菱形 | 原版宽菱形使用约 20° 侧边；此前统一二倍矩形导致比例不同 | 依据内容比例计算侧边角度，保留全部内容角落在菱形内 |
| Canonical 150，紧凑圆+图片+标记 | 原版三行是中文标题 / `alpha bravo charlie` / `delta`；旧 DEditor 是中文标题 / `alpha bravo` / `charlie delta` | 对 canonical 紧凑圆进行一次外径估算与一次重排，图片提供中央列最小宽度，标记预留独立侧列；浏览器最终三行与原版一致 |

紧凑圆的第二次排版依据原版估算/协调阶段的规则，次数有界，不通过反复扩大到收敛或写入猜测宽度追截图。未设置 canonical 宽度的节点与其他形状不进入该路径。150 样例浏览器最终外径约 302 CSS px，原版截图按图片尺寸比例估算约 309 px；字体测量、行高与内边距仍存在近似差异，不记录为逐像素一致。

原版不使用本组样例中的旧 `fo:max-width` 属性，DEditor 则保留原有兼容行为。两类宽度已用分开的样例验证，不以删除旧属性支持来追求原版外观。所有布局变化不改归档原始字段，未改文件加载及保存语义。

只读查看了本机已安装原版的形状声明和布局阶段，核对“能否自定义宽度”、圆角、菱形几何、紧凑圆分阶段宽度规则；没有把原版实现文件复制到仓库。产品几何与测试由本项目独立实现。

独立复核指出菱形在等宽高边界有跳变，重新核对原版后确认这是原版的明确分支：内容宽 ≥ 高使用 20°，内容宽 < 高从 45° 起随比例增加到 70°；因此 100×100 与 100×100.01 会落入不同分支。保留这一兼容规则并增加边界回归，没有擅自平滑。DEditor 的通用形状函数接收已含内边距的矩形，原版在原始内容上判定再加内边距，边界位置与最终尺寸仍属于上文明确保留的几何近似范围。

## 验证

- `npm run test:xmind`：119 项通过。
- `npm run test:xmind-closeout`：8 个 canonical 宽度节点、72 个圆形组合（3 宽度×有无图片×有无标记×3 字号×亮暗）、280 分支、96 形状/主题组合、500 混合归档及 51 历史修订通过。圆形专项校验完整文字、有限几何、正圆、内容包含、标签外置和源数据不变。
- `npx tsc -b --pretty false` 通过。最终完整构建由主 agent 汇总，不将此前包当成本次形状改动的原生验收。
- 浏览器实际画布三组 canonical 工作表的折行、外径、宽度控件禁用、切换为圆角矩形后启用及单次撤销恢复禁用通过；三组最终截图与 DOM 测量保留。
- 11 个自建单表文件的生成时 SHA-256 与原版操作后相同。打开、原样序列化精确一致；另改根标题的归档往返保留子主题 canonical 宽度及其他字段。
- 首次新增断言错误地要求 300 宽度必须改变自然宽度已超过 300 的节点，失败后改为只要求 150 有有效改变，同时保留 300 的内容尺寸/原始字段验证。未用该失败冒充产品缺陷。
