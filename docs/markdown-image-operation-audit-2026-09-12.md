# 阅读编辑 H01–H04 图片操作验收（2026-09-12）

本次在 B/C 输入剪贴板检查后继续图片专项。全部自建文本/图片；浏览器的图片复制 IO 为明确模拟，原生系统目录、真实磁盘资源闭环和真实 PicGo 账户不由本子任务操作。

## 已复现和修复

1. **H02/H03 图片路径维护误删替代文字。** 原文 `![a \](b](old.png "title")` 的 alt 包含转义右括号。旧定位取第一个 `](`，将标签内部的字符误认成路径开头，重写后变成 `![a \](new.png "title")`，丢掉 `b]`。现在按 Markdown 标签括号和转义定位真正结束位置，只替换目标 URL；嵌套标签、引用式图片、标题和其他文字保持。独立测试有修复前失败，浏览器使用同样标签收集图片后保留全部 alt，一次撤销恢复原文。
2. **H01 图片宽度显示与实际保存不一致。** 输入 `0`、`10001`、`2.7` 会按既有规则限制/取整到 `1`、`10000`、`3`，但输入框仍显示旧数值。现在提交时同步回显规范化的数值。独立测试有旧 `0 !== 1` 失败对照；浏览器检查数值框、源码宽度一致，清空恢复自动宽度不受影响。
3. **H01 标题控件错叫 Alt text，实际 alt 无独立编辑入口。** 原图片 `![自建图片](... "title")` 的“Alt text”框显示 `title`，修改的是 title。现在原控件准确标为“图片标题 / Image title”，既有图片悬浮操作区增加真正的“图片描述（alt）/ Alt text”。浏览器还复现上游标题的异步渲染把实际 `img.alt` 覆盖为 title；包装层现在观察该属性并恢复独立 alt。正文源码、实际图片无障碍名称、标题和宽度分别核对，不能只看源码判通过。
