# 输入代码围栏后表格保存损坏（2026-09-19）

## 范围、复现和原因

用户提供 `/Users/damon/Documents/workfile/测试.md`，反馈表格保存错乱，并补充最后添加了 PlantUML 围栏。本次只修复输入围栏造成后续源码损坏，未调整图表外观或此前已记录的 H-TAB-01。

最初提供的文件已经缺少表格分隔行，部分单元格被截断，无法仅凭这份结果确定丢失原文。已留存只读副本，没有修改用户文件。只用自建文件进行编辑、保存和原生测试。

自建复现包含：前置列表和引用链接、三行五列表格、表头粗体与 `<br>`、后置普通代码、HTML 和引用定义。在表格前新建段落，逐字输入三个反引号及 `plantuml`：输入 `p` 时画面仍正常；到 `l` 时后面表头源码被截去一部分，继续输入逐步吞掉后文。此时 ProseMirror 中的表格仍在，保存把已坏的源文写入磁盘，重新打开才明显呈现损坏。

两个原因叠加：

1. 为富文本复制增加的容错围栏识别，把输入过程中序列化出的“每个反引号都转义”的普通段落误认成未闭合代码块。
2. 局部解析为了解析引用链接，在当前块后追加了引用定义上下文。错误代码块吞掉这段上下文，缓存的源码终点超过当前块长度；下一次输入按这个过大范围替换，误删相邻块。

## 修复

- `markdownFence.ts` 保留完全转义的反引号文字，包括代码内部的转义结束标记。标准围栏及既有拆分、部分转义 HTML 围栏继续兼容。
- `markdownVisual/document.ts` 统一局部块范围构建。引用上下文不属于当前块；解析范围越界或出现多个块时，使用当前块实际长度的保守映射，避免连续输入删除相邻正文。普通更新、脚注单块/多块投影均使用同一限制。
- 表格专项新增 F06 两组、12 个组合；围栏显示专项新增完全转义文字、LF/CRLF 以及既有容错 HTML 的实际渲染断言。分类入口把表格专项同步关联到输入、内嵌块、生命周期、持久化与保真类型。
