# DEditor 1.0.3 macOS 长 Markdown 性能更新

本轮保留版本号 1.0.3，重新发布 macOS Apple Silicon 安装包及配套构建元数据。Windows EXE 保留原附件，本轮未重打 Windows 安装包。

## 改动

- macOS 长文档的阅读编辑器采用独立的同源渲染文档，复用应用运行时；适配快捷键、焦点、弹窗、右键菜单、表格及图块的跨文档操作。
- 只访问阅读编辑的文档暂不创建源码编辑器；首次切到源码时恢复原位置。
- 主窗口在原来最近 8 个视图之外，最多额外保留 12 个长文档视图。额外预算估算为 768 MiB，分屏共享，闲置两分钟到期，关闭标签或超预算时卸载。二级窗口与带播放器、内嵌页面的文档沿用原来的保留规则。
- 添加最多 48 MiB 序列化载荷的解析缓存；命中时复用文档模型和源码索引，源码不一致时重新解析。
- 减少代码块和保留块的重复 DOM 更新、行号计算及非必要布局，复用普通内联公式输出。
- Rust 文本读取和目录枚举移到后台执行；命名管道作为文本打开时返回错误，避免等待写入方。

缓存预算是估算值，不能等同于整个 WebKit 进程的 RSS 上限；共享引擎、分配器与解码图片存在额外开销。

## 验证与限制

- 本轮发布前重新运行 test:all：文本序列化、13 组阅读组件、表格生命周期、5 轮文件拖放分派、4 轮更新流程、48 项 Rust 库测试及生产构建。
- 同机 WebKit 生成样例：每份 1458 行、52 个表格，轮换 18 份后回点前两份，原策略为 1116 / 1061 ms，额外视图缓存为 272 / 261 ms。采样进程峰值为 1495 / 2109 MiB，增加约 614 MiB。
- WebKit 回收样例中，关闭标签使活视图从 9 降到 8；模拟额外缓存到期后降到 7，保留标签和源码。
- 已安装前一构建，并从正式版文件树实点用户指定的同批报告。打开第 9 个标签后回点两份报告，界面工具返回截图为 1474 / 1589 ms；此计时包含工具开销，不能和内部首帧计时直接比较。
- 首次打开和真正淘汰后的重建仍可能耗时数秒，尚未全面达到 1 秒目标。
- 组件与生成样例不代表 Windows 安装包、物理输入法或系统拖放验收。当前原生待办仍以 pending-tasks 为准。

### macOS 未公证版本安装

1. 安装前，在 DMG 所在目录执行 `xattr -cr DEditor_1.0.3_aarch64.dmg`。
2. 打开 DMG，将 DEditor.app 安装到 /Applications。
3. 安装后，执行 `xattr -cr /Applications/DEditor.app`，再启动应用。
