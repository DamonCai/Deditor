# 阅读编辑复用现有页脚搜索组件（2026-09-14）

## 最终范围与实施

用户明确要求“其他的搜索组件是现有”：阅读编辑直接复用已有组件，保留现有样式，再验证定位与高亮。上一版新建共享面板并重设字号、间距、替换行布局的做法已撤回；此前200px输入宽/66px双行高度不是本次验收基准。

- 源码/实时预览恢复使用 CodeMirror 默认搜索面板，删除上一版 `sourceSearchPanel.ts`，移除 `Editor.tsx` 中的自定义面板配置和全部 `deditor-search-panel` 控件样式、额外显示文案。
- 阅读的 `SearchPanel.tsx` 只是现有组件的适配入口：使用一个空、不可编辑、未注册 editorBridge 的 CodeMirror 宿主，调用原生 `openSearchPanel` 直接创建库自带面板。宿主不复制正文，其空滚动区不显示、不接收 Tab；没有复制面板 DOM，也没有提供 `createPanel` 或另写控件样式。
- 输入和选项使用原面板；查找/替换/关闭事件接到阅读文档。保留源码多选 all 功能；阅读本来不支持不连续多光标，原生 all 控件在阅读侧禁用。只读使用原生只读面板，不创建替换控件。结果计数/错误仅供辅助技术播报，不新增可见布局。
- 阅读搜索仍放在正文滚动区域之后。保留此前定位与高亮修复：ProseMirror 独立装饰呈现匹配，明确滚动阅读容器，Enter/Shift+Enter 时搜索框继续持焦。关闭/无结果清理装饰，不污染正文或撤销历史。主题重建后恢复高亮，重建面板不抢走外部按钮焦点。
- 普通代码预览通过 CSS Custom Highlight 绘制命中文字，不改 Shiki DOM；未新增旧 WebView、复杂保留 HTML/图表 SVG 全源文匹配、真实 IME 等结论。

## 四轮验证

### 1. 与原有组件实际对照

期望：复用的是原有 CodeMirror 面板，源码自身未被重新设计。

实测：固定副本 `Editor.tsx` 与 `4a5c9b7` 逐字节相同；当前工作区 `styles.css` 原 CodeMirror 搜索区段逐字一致。DOM 回归对比阅读和独立原生 CodeMirror 面板的所有直接子控件类型、名称、顺序、文本一致。

1280px 真实浏览器：两侧面板高度40.890625px、查找/替换输入框宽153px高24px；next宽44.515625px、previous宽66.796875px、replace宽60.7734375px、replace all宽75.7578125px。每个控件的x位置、字体、margin相同，恢复原有单行。

结果：通过。没有使用上一版自定义面板作为比较基准。

### 2. 正向与边界查找

期望：中文长文、表格、代码命中可见；正反向/循环/单命中再次Enter均定位，查询为空/无结果/无效正则时不误修改。

实测：实际中文远处结果定位并高亮、输入框保持焦点；搜索专项覆盖Unicode、大小写/全词、无效/零宽正则及恢复、替换命名捕获、字面美元符；只读面板无替换输入。

结果：通过。输入法相关仅按键事件防护测试，不是系统组词验收。

### 3. 布局与连续操作

期望：窄窗延用现有换行规则，主题切换保留高亮，不抢外部焦点，替换后可精确撤销。

实测：暗色720px两侧面板高度均75.78125px，查找行与替换行的全部控件坐标/宽度一致；主题点击后焦点仍在Theme测试按钮，高亮保留。实际替换中文后Esc关闭、一次Undo恢复自建原文，字段Enter操作后回到查找输入。源码/阅读往返均使用现有面板。

结果：通过。

### 4. 回归与构建

10组搜索、107阅读集成、13基本操作、6会话连续操作、8模式焦点、145通用和8分隔线通过；生产TypeScript/Vite构建通过。整合测试中有一条仍断言被撤回面板的 `Replace with…` 文案，已改为验证原生替换字段 `name=replace`，再次通过。

最终验证采用基于 `4a5c9b7` 的固定搜索副本，保护同时进行的分屏、列表、预览与历史改动；当前工作区的搜索专项也通过。不能将固定副本测试概括为并行最新整合代码全部通过。
