# Markdown 文件链接修复（2026-09-13）

用户范围：实时预览将文件链接显示为可点击的文件名；阅读编辑文件链接在 DEditor 内打开；同时支持不带 file 协议的绝对路径和相对路径。

## 原因与实施

- markdown-it 默认拒绝 file 协议，`[文件名](file:///...)` 被当作正文并可能被 linkify 局部识别。仅允许 file 协议通过，其他协议继续沿用原校验。
- 共享 DOMPurify 显示层还会去掉 file href。为 Markdown 建立独立清理实例，只保留 a 元素的 file href，不更改其他 HTML 使用方；脚本链接仍被清理，file iframe 仍被移除。
- Milkdown 正文链接 schema 同样会清空 file href，现仅对 file 链接保留地址，其余协议仍使用上游清理。
- 阅读链接悬浮卡片在 ProseMirror 外，原本走浏览器默认跳转，且其 file href 被清空。现由本编辑器宿主拦截该卡片点击，读取卡片所持原地址，与正文链接共用路由：HTTP/HTTPS 进入系统浏览器，本地目标调用 openMarkdownFileLink / openFileByPath 在应用内打开。
- `/Users/...`、`./file.md`、`../file.md` 使用现有本地路径解析；相对路径基于源文档目录，中文/空格/编码的井号和百分号只解码一次。正文仍可单击编辑，Cmd/Ctrl+点击打开；悬浮卡片中的地址单击打开。
