# Windows 1.0.3 排查与发布

本轮于 2026-10-25 开始，2026-10-26 收尾，基于 `26b983e`，起始工作区干净。三个 agent 分别核对 Markdown、原生文件分派和 Windows 打包链，主 agent 集成、验证和发布。只使用本轮生成的文档、测试替身和隔离应用，不读取日常应用状态或已有用户文档。

## 确认并处理的问题

- 启动恢复与系统拖入文件存在竞态：拖放监听先打开新标签，随后 `loadPersisted` 的 `replaceTabs` 覆盖它。修改前用真实恢复/store/文件打开路径和隔离 IPC 稳定复现。现在拖放等待本窗口恢复结束（包括恢复失败），卸载和已提交关闭时取消后续处理；正常路径保留文件、目录分派及错误提示。回归包含真实 App 挂载和原生事件监听接线。
- `build-win.ps1` 在 Windows PowerShell 5.1 使用默认编码读取和重写 UTF-8 manifest，会损坏非 ASCII 内容，含中文的 JSON 可直接解析失败。现在显式保留 UTF-8，无版本变化时不重写。
- 打包脚本复制 `bundle` 下所有历史安装包，可能把旧版混入当前交付目录。现在按本次版本匹配 MSI/EXE；原有产物不删除。
- Windows Rust 测试存在两类可移植性问题：默认图片路径用 `/` 字符串断言；非阻塞监听器接受的 Windows socket 继承非阻塞状态，读取产生 `WouldBlock`。改为路径组件及实际字节断言，测试服务器明确使用带超时的阻塞读取，并新增延迟分段 POST 回归。没有修改图片下载/上传产品逻辑。

## Windows 原生与交付结果

- 最终 `npm run build:win` 成功，生成 1.0.3 x64 MSI 和 NSIS EXE。仅上传用户要求的 EXE；MSI 留作本地产物。EXE 大小 `9575937`，文件/产品版本均为 `1.0.3`，SHA-256 `08ba648c2408f6e60cd8f5f3d048adc1cacb13d9f071aa86d7ebb5583ea425fb`；`scripts/` 副本与 bundle 原件哈希一致。EXE 未签名。
- 隔离原生程序使用最终产品前端及独立 identifier，保留原生菜单和真实 Rust 文件接口，没有注入模拟 drop。为排列拖放源/目标，隔离配置将窗口置顶；这不进入正式配置。
- 本轮首个隔离配置把 Windows 绝对 `frontendDist` 误判为 URL，出现目录索引。改用相对 `../dist` 后重建并观察真实产品界面；前一个包不算原生验证通过。
- 修正后通过自建文件命令行打开观察到精确的 `WIN103_ORIGINAL_WINDOW` 内容；实际 Ctrl+Shift+N 创建独立空窗口。文件对话框自动化控件定位不稳定，没有把失败尝试记为保存或打开面板通过。
- WIN-04：在自建 fixtures 的 Explorer 窗口尝试拖 `drag-中文.md` 到空窗口正文，工具因终点属于 `msedgewebview2.exe` 而不是源 `explorer.exe` 拒绝。未产生有效 drop，目标仍空，保留待办；不会将打开面板、argv 或合成事件替代系统拖放。
- CLIP-03：本机 Windows API 只有单窗口起止点拖动，没有跨显示器持续按住、分段移动和跨屏观察接口，保留待办。
- 没有安装正式包或改动日常应用，不宣称完成安装/升级、搜索图标及非打包进程真实路径验收。自建 fixtures 按生成内容重新核对，验收程序收尾停止，测试证据保留。
