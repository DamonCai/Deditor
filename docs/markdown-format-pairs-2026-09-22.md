# Markdown 格式符空选区自动配对（2026-09-22）

## 本次实施

阅读编辑现复用“自动配对”总开关，为空选区输入的 `*`、`_`、反引号、`$`、`~`、`=`、`^` 生成闭合符。光标停在中间；继续输入内容后，键入自动生成的闭合符会向右跳过；空配对中按 Backspace 同时删除两侧。括号、引号的独立偏好和既有选区包裹保持独立。写作设置中英说明同步包含格式符，方便关闭。

- `*` / `_` 可继续输入第二个、第三个开符，形成粗体或粗斜体；反引号、`~`、`=` 可继续输入第二个开符。`~` 是下标，`~~` 是删除线；`==` 是高亮，单个 `=` 仍是普通文字。
- 只记录当前输入生成的闭合符。已有文档中的符号、恢复后文档中的符号不会被当成自动生成的闭合符跳过或删除。
- 段落开头的空配对遇到空格时交回既有 Markdown 输入规则；`* ` 列表、`*** ` / `___ ` 分隔线、三个反引号的代码围栏及 `$$ ` 公式保持原行为。代码默认语言和显式语言不变。
- 段落开头继续输入长符号串时释放自动生成部分，避免四个星号变成六个、下划线被误跳过。四至六个星号/下划线、四至五个反引号、三至五个波浪号均与关闭自动配对时的同一输入序列对照。较长围栏和分隔符仍使用原有输入规则，本次不新增识别限制或强制转换。
- 转义开符不配对；单词内部的 `_` / `=` 保留标识符和运算符输入。生成配对正文中的反斜线转义闭符作为正文输入；行内代码遵守反引号自己的转义语义。
- 中文输入法 composition、只读、代码块和现有源码投影中的普通输入不触发新的配对。此处 composition 结论来自组件事件测试，不能替代真实候选窗口验收。

## 源文和撤销

新配对暂存为现有 `deditor_inline_source` 投影，并立即同步实际 Markdown 源文；因此半输入保存也保留当前可见的开闭符，不经过普通文字序列化而被转义。完成闭合后局部恢复阅读样式，保留既有文档历史；连续生成、正文输入和闭合可作为一次编辑撤销，保存/重做/重挂载均核对源文。

同时修复 `MarkdownDocument.textRanges` 的具体错位：引用/列表段落尾刚输入空格时，解析器可能省略该尾空格，而编辑器仍保留它；原映射因此退回线性位置，未计入引用前缀。现在先匹配一致的正文流，再以源文实际字节验证并补上省略的水平空白。带行内代码内侧 padding 的场景优先外侧闭合边界，避免把真正的尾空格错误映射到反引号内部。表格中的 `&#32;` 保留原拼写。

## 保存后的连续输入（第 13 组）

同一编辑会话逐键输入 ` **word` 后，分别执行 `flushDocument`、`saveFile`，以及设置 `autoSave=afterDelay` 后等待 1.55 秒调用实际 `saveAllDirty` 入口。三条路径均断言生成配对的位置和宽度保留、源码投影仍挂载、正文和写盘内容精确为 `Before **word**\n`；随后逐键输入两个星号均跳过生成闭合符，继续输入“后”精确得到 `Before **word**后\n`。

此组使用默认 `formatOnSave=false`。组件测试挂载真实阅读编辑器并执行真实保存入口，但未挂载 App 的自动保存调度 effect，因此不等于真实定时器 UI 验收。源码确认 App 的 afterDelay 定时器在 1500 毫秒调用 `saveAllDirty`，该路径仅刷新文档，不主动关闭行内源码投影。
