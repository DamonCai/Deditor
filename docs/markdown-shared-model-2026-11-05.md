# 长 Markdown：共享语法树与按视口显示

任务来源：当前会话用户要求长 Markdown 首次打开、视图逐出后重建压到 1 秒内，改完安装并从文件树实测同批报告。用户接受用户无感的视口布局方案。本轮没有收到新的远程发布请求。

**当前状态：最终包已安装并从文件树完成同批八份报告实测；本轮首次阅读视图样本为 603–900 ms，最大报告缓存切换 379 ms、关闭后重建 887 ms。目标在这批实测样本中达到；不代表任意 Markdown 或任意机器负载下的硬性最坏耗时保证。**

## 实现

- Worker 原始语法树供初始化的源码索引和 Milkdown 各自克隆使用，减少重复词法解析。与原 Milkdown 文法严格对照；只匹配第一次完整输入，随后恢复原解析器，保留失败回退和后续片段解析路径。初始化结束释放准备 Promise 和原树引用。
- 完整 ProseMirror 文档模型始终存在。长文的普通顶层标题、段落、列表、引用及文本表格按视口建立 DOM；源码、搜索、选择、剪贴板、编辑和撤销继续基于完整模型。首屏后扩大到 1200 px 滚动预加载范围。显示过的节点保持存活。
- 含媒体、HTML、未知节点或带公式编号锚点/引用的容器保留原视图和副作用。普通行内公式随所在正文/表格块按视口显示，完整公式仍在模型内。带嵌套标题的列表/引用也保留原视图，以保持目录几何定位。自定义 CSS 启用后完整显示，新插入的节点也不延后。组合输入期间暂缓排队显示。
- 普通屏幕外代码保留完整惰性文本、行结构及行号空间，接近视口后添加高亮；进入编辑立即建立完整 CodeMirror。HTML、图表和公式沿用原路径。普通代码工具栏只挂载当前可用的控件，语言或自定义 CSS 变化时恢复原控件和顺序。未进入 CodeMirror 时不创建其高亮扩展。
- 显示估算变为实际高度时补偿可见根块的位置。滚动时保存模型位置与像素偏移，视图逐出后按相同源码恢复可见块，避免只记绝对 scrollTop 带来的位置偏差。标签关闭后随会话释放。
- 目录高亮对自然文档流采用二分几何查找，自定义 CSS 保留原扫描路径。视口状态缓存节点身份集合及首批显示集合，避免每个 NodeView 重扫块列表；事务显示位置用集合查询。

这轮改动涉及九个产品文件；没有修改 Rust 文件接口或用户 Markdown 文件。内存模型与显示组件分离是核心变化，继续增加文件读取缓存无法消除整篇 DOM 的首次布局成本。

## 同机原生采样

独立验收包使用正式代码和正式样式、独立 identifier，未注册文件关联。直接从文件树点击用户指定的报告。点击后等待程序的双动画帧诊断落盘，再读取界面，避免截图/AX 采集插入被测时间段。

### 公式密集生成样例

同机、相同正式样式 WebKit 工具，2402 行、1200 个行内公式的两份生成长文，串行前后采样：首次显示分别从 2724/2922 ms 降到 1015/600 ms；缓存切换从 2088/2327 ms 降到 362/352 ms。初次创建的公式显示由 1200 个降到 36 个。另一轮优化样本为 648/457 ms，但不挑选较快样本覆盖串行复测的 1015 ms；该更密集样例仍有一次略超 1 秒，不能宣称普遍最坏耗时达标。采样时存在其他应用的 CPU 负载，未主动停止或改变用户进程。

代码预览 CSS 布局隔离实验未显示稳定收益，已撤回；最终包不包含该实验。
