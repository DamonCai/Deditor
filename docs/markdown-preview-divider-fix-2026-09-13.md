# 实时预览分隔线误选修复（2026-09-13）

范围：主界面“实时预览”左右分隔线拖动时，右侧预览正文被意外选中。保留同一套侧栏分隔线处理，不调整图表自身的内部比例或 Markdown 数据。

## 复现与修改

在无真实文件、无持久化的 `tests/markdown-preview-divider-review.html` 中，用原 App 的 mousemove/mousedown 逻辑、真实 EditorSlot + Preview 自建中文样例复现：1280×720 下从 `(640,170)` 拖到 `(900,280)`，预览比例变为 29.7%，但浏览器同时选中了标题、前两段及第三段开头。

原处理只改了鼠标样式，没有阻止浏览器选区默认行为。新增 `beginPaneResize`：仅主指针左键开始；pointerdown 阻止默认选择并捕获指针；拖动期间通过临时类（含 WebKit user-select）和 selectstart 守卫禁止新选区；pointerup/cancel、capture 丢失、失焦、丢失左键状态和组件卸载恢复。不会清除用户已有选区，不修改 body 原有行内样式。App 切换文件、模式、侧栏或专注模式时结束旧拖动。侧栏沿用相同分隔线处理。

## 验证

1. 行为与边界：新增 8 组专项，覆盖正常拖动、右键/非主指针、其他指针干扰、取消/捕获丢失/失焦/漏 mouseup、原有中文选区及内联样式保留、卸载/移除节点、连续拖动。全部通过，已接入 `test:regression`。
2. 真实浏览器：同一自建文档、同一路径，比例仍为 29.7%，选区为空，松手临时类已移除；随后鼠标选择预览第一段能选到完整文字，再次拖动保留这段原有选区。暗色 720×900 来回拖动（预览 15.3% → 69.4%）仍无新增选区。没有用程序创建 Selection 代替实际拖选。
3. 相邻回归：`test:regression` 145 通用 + 8 新增通过；`test:markdown-sequence-session` 6 连续会话 + 8 模式焦点通过；`test:xmind` 119 通过。生产 TypeScript/Vite 构建通过。
