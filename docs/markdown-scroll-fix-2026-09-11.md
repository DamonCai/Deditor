# Markdown 输入位移修复（2026-09-11）

用户反馈编辑时页面还在移动。本次复现确认了块高度突变：自建 Mermaid 五节点纵向图高 512px，进入六行源码后原实现降至 151.75px，后续正文上移 360.25px。

## 修改

- 代码、图表和公式进入源码时保留原呈现高度；保留 HTML 块也按原高度占位。源码超出原高度时仍能自然增长。
- 输入立即写回 Markdown，但不逐键重绘隐藏预览；退出编辑后再生成更新后的呈现。
- 未改内容直接复用现有预览；图表新结果在独立容器完成后替换，避免反复展示加载占位内容。
- 异步渲染校验源码与版本，输入或撤销使结果过期时取消，避免旧结果覆盖当前内容。
- 不锁定文章滚动。光标超出可视区时，原有必要滚动、查找、目录、滚轮行为继续生效。

## 滚动测量的校正

排查途中曾观察到输入前后 108px 等位移，后续发现对定位器执行按键/点击会先自动滚动目标，不能据此认定为编辑器自动滚动。最终证据使用先滚动到可见位置、坐标点击、直接键盘输入，且在输入前后读取位置；根节点 y=0、文章滚动值稳定。临时追踪代码已移除。先前“嵌套编辑器自动滚动”的判断没有得到独立证据支持，不作为已确认根因。

真实输入法候选窗口、原生 WKWebView 焦点行为、Windows 仍未完成验收；本次修复覆盖已复现的块高度变化与预览重绘问题，不宣称消除所有平台、所有文档的位移。独立 XMind 任务的未提交改动未纳入本次提交；完整自动化在仅包含本次暂存内容的快照运行。
