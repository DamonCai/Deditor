# Markdown P0：组词历史与输入边界验证

日期：2026-09-11。用户要求按优先级开始，且阅读编辑应与实时预览保持相同正文样式。本次先处理 P0 输入及历史可靠性；**P0 的真实 IME 和双平台验收仍未完成**，不将自动化通过等同于全面完成，也未跳到 P1 行内源码显隐。

## 问题与修改

旧会话仅按 750ms 间隔合并相邻编辑。用 `正文 → 正文n → 正文ni → 正文你`，在候选更新间停顿超过此窗口，撤销会恢复中间拼音 `正文ni`，而非撤销完整词。此问题已通过历史模型测试复现。

现按 composition 开始/结束记录一次完整组词的净修改，取消组词不新增历史，也不清除原来的重做分支。相邻两次组词及普通输入保持独立步骤。正文、表格、内嵌代码/保留块以及 Markdown 源码模式共用这套规则；HTML 和其他代码文件继续使用原有历史。

捕获阶段监听同时覆盖会阻止事件传到 ProseMirror 的内嵌 CodeMirror。组词确认后等待最终输入处理，再完成历史步骤和视图同步；下一次普通按键或离开编辑区、卸载时也收尾。组词期间不以外部文本整篇替换活跃视图。新增“结束时撤销”测试发现本次实现中的额外 flush 会将旧视图覆盖到已撤销内容，现已移除此重复写回，并保留回归用例。

滚动保护补充了折叠 Range 没有可用矩形的处理：只读测量相邻字符，空段落使用自身位置。不修改 DOM 和原生选区；用户主动滚动仍优先。这是对缺失几何数据的防护，尚无修复版真实拼音结果证明其覆盖了之前的原生跳动原因。

本次没有修改 `preview.css` 或 `markdown-visual.css`，继续使用既有共享排版。
