# 阅读编辑表格键盘深测（2026-09-27）

本专项按用户最终明确的交互执行：**只选整张表后按 Tab 增加整表缩进，Shift+Tab 减少；不要求同时选上一行，也不依赖前置列表。** 持久属性、解析/序列化和显示由主 agent 实现，本专项负责按键分流与真实组件回归。

## 行为与修复

`tableKeys.ts` 识别两种整表选择：`NodeSelection(table)`，或同时覆盖全部行与全部列的 `CellSelection`。Tab 改 `table.attrs.indent`，保留表格其他属性、内容和选区方向；每步独立撤销。在 0 级按 Shift+Tab 消费按键而不派发修改。1×1 表中普通文字光标不等同整表选择，仍保留末格 Tab 增行。

确定修复了两项原有误操作：Ctrl/Meta/Alt+Tab 不再被末格逻辑当成普通 Tab 增行；跨表格或跨多个单元格的普通文字范围不再因 `isInTable` 只检查选区 head 而被当成单格导航。后者在正反方向均消费 Tab/Shift+Tab，保留源文和选区；不引入未经请求的跨块缩进语义。要缩进表格需使用明确的整表选择。

后续浏览器把空单元格格式输入问题定位为确定缺陷：清空第一格 `one` 后输入 `**`，画布配对显示在第一格，源文却插到第二格 `two` 前；继续输入形成 `boldtwo`。`document.ts` 的位置映射只记录空 paragraph/listItem，mdast 空 tableCell 没有 paragraph 子节点，导致该光标被映射到邻格最近文字。现为空 tableCell 增加独立零宽源码锚点；带缩进/垂直对齐隐藏注释时，锚点位于注释之后、尾部填充空白之前，避免元数据错位或可见前导空格。修复后相同真实浏览器路径通过，DOM 组件也补齐回归。

## 操作矩阵

| 范围 | 验证结果 |
| --- | --- |
| 普通表、仅表头表，首格 Shift+Tab | 停留首格，无源修改 |
| 每格 Tab/Shift+Tab、末格 Tab | 顺序切格；最后一格只增一行，增行与后续输入分别单步撤销 |
| 整表节点选择、全单元格正反选择、1×1 | 两次 Tab、一次 Shift+Tab、保存重开、单步撤销重做保持缩进和选择语义 |
| 局部矩形 CellSelection | Tab 仍导航，不改整表缩进 |
| 前段落/相邻列表→表格、同表跨格 TextSelection | 正反方向、Tab/Shift+Tab 均无损保持，不插空格、增行或折成单格 |
| Enter/Shift+Enter，表头、空格、正文、末格 | 在原单元格内插持久 `<br>`；未碰相邻格；保存、撤销与重开通过 |
| 矩形选择 Enter | 进入 head 单元格编辑，不清空矩形 |
| 矩形选择 Backspace/Delete | 清空选中内容，保留表结构，单步撤销 |
| 段落 NodeSelection Backspace/Delete | 清空原格并留在原格；整表 NodeSelection 删除则删除表格，单步恢复 |
| 单元格文本首尾 Backspace/Delete | 不误删相邻单元格或表结构 |
| 相邻段落 ArrowLeft/ArrowRight | 进入相邻表格最近单元格，源文不变 |
| 表格位于列表项内 | 末格增行保留表归属和其他列表内容，撤销恢复原始字节 |
| 单元格内嵌套列表 | Tab 按格导航；Enter 在列表文本内换行，保存重开保留结构 |
| 单元格逐键 `- `、`+ `、`1. `、任务标记、标题/引用标记与管道符 | 使用实际 DOM 输入事件及 MutationObserver，文档保持有效、相邻格不变，保存重开一致 |
| 缩进表的空/粗体/带 valign 与换行表头 | 缩进扩展只保存在首表头源中，不泄漏为可见文字，格式与垂直对齐保留 |
| 缩进表首列插入/删除/移位、插入新表头行 | 缩进始终属于表格，元数据只有一份，内容/标记/对齐随单元格保留 |
| 初始为空、清空后输入普通文字/粗体/行内代码 | 内容始终写入原格，邻格不变，单步撤销重做、保存重开一致 |
| 全空表的首/中/末表头与正文，普通/隐藏元数据/嵌套列表/CRLF | 24 格组合的配对格式保持原格、原属性与精确历史；注释不产生可见前导空格 |
| 只读、组合输入、修饰键 | 不触发整表缩进；真实 compositionstart 后 Tab 前后源文和缩进不变 |

## 执行结果与证据边界

- `node scripts/test-markdown-table-shortcuts-deep.mjs`：23 组通过，包含上述多维循环。
- `node scripts/test-markdown-table-audit.mjs`：既有 34 组通过。
- `npx tsc -b --pretty false`、`git diff --check` 通过。
- 测试装载实际 `MarkdownVisualEditor`、真实 parser/serializer、源文与历史层；键盘派发实际 DOM `keydown`。逐字输入派发 `keydown/beforeinput/input` 并补 JSDOM 缺失的默认 DOM 插入，由 ProseMirror 的 MutationObserver 产生事务。文件写入为可断言替身，不等同原生磁盘验收。
- 快速直接调用 `handleTextInput` 的初版辅助曾把 `1. item` 变为反序；换为 DOM 路径通过，主端实际浏览器也通过，未据此改产品。整表 compositionstart 本身会准备替换全部选择，不将其正常清空误称为 Tab 删除。
- 首轮 `**bold**` 向邻格写入的观察曾暂怀疑 DOM 辅助；后经主端浏览器明确复现并追到空表格源码映射，已按真实缺陷修复。配对行内源码使用同一可编辑 DOM span，修复后的粗体/代码路径均已补入组件回归，不再保留先前的辅助不支持推测。
- JSDOM 的无布局矩形不能证明 ArrowUp/ArrowDown 的视觉光标位置，亦不替代真实候选窗、系统键盘、macOS/Windows 原生验收。精确外观和实际浏览器操作证据由主 agent 汇总。
- 列表内表格改动会重新序列化包含它的列表，列表标记和表格填充空白可能规范化；结构与正文保持，撤销恢复完整原始源字节。未将重新序列化后的所有空白都称为原样不变。

未修改用户文档，没有启动原生 UI；本专项没有提交或推送。
