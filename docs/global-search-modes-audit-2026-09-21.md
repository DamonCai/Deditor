用户要求沿阅读等其他模式横向排查。本次范围是全局搜索结果的打开、高亮、定位及面板隔离，不代表整个编辑器所有功能的全量验收。

## 发现与修复

1. Markdown 实时预览原来只选中左侧源码，右侧没有命中标记。新增实际 EditorGroups 测试在修改前失败，修复后通过。现在等待预览完成后按源块和出现次序标记目标，保留 Shiki 内部结构；正文和长代码的目标在预览中居中。重绘主题后恢复标记，换文件、换模式、换面板、重新搜索、修改及手动操作时清理。手动滚动解除居中，恢复滚动联动。
2. HTML／CSV 纯阅读隐藏了源码，也不注册活动源码 bridge，全局搜索仍等待该 bridge。现在搜索结果会展开源码与预览双栏，选中源码中的精确范围，包括仅存在于 HTML 属性或 CSV 引号中的文本。修改仅作用于当前面板。
3. 等待期间的模式校验补齐 CSV 和 HTML 模式，用户改变模式后取消旧请求。

预览文本没有对应的源字串时（如链接目标、标签、图表源码），保留左侧源码定位，不把标记强加给另一个可见出现位置。预览中不跨 iframe 搜索；没有新增文案或修改渲染内容。
