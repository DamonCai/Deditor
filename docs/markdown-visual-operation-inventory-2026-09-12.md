# 阅读编辑操作盘点（2026-09-12）

本表按当前代码及上游编辑组件列出阅读编辑的操作面，用来安排验收和防止漏项。本表最初仅作盘点；后续已按此目录执行修复和验收，结果见下方链接。**有入口、有测试、实测通过是三个不同状态；下表不能当作全量通过报告。**

**逐项验证与最终整合结果：**见[实际验收与修复进度](markdown-operation-verification-2026-09-12.md)。本表的证据栏保留盘点时状态，最新结论以该记录及其引用专项为准。

范围：Markdown 阅读编辑，以及直接影响其内容、光标和历史的保存、模式、标签与设置操作。排除导入导出细节、字体选型、HTML/XMind 专用编辑器。已删除的“只读”模式不列为产品入口。

## 如何快速用这张表

已提供统一入口：`npm run test:markdown-operations` 运行 Markdown 启动、核心、阅读集成和操作专项；`npm run test:all` 继续检查其他编辑器、XMind、语法等回归（生产构建另行执行）。命令不替代原生输入法、真实拖拽、账号和长期压力验收。修复与环境结果见[逐项验收记录](markdown-operation-verification-2026-09-12.md)。

1. 先跑文末的基本操作烟测，发现故障立即记录最短操作链。
2. 按操作编号补测边界，每个失败保留原文、按键、光标位置及预期结果。
3. 修复后同时检查文字、光标、页面位置、保存和撤销；再跑相邻操作，防止修一处坏另一处。
4. 每份通过记录绑定代码快照和运行环境；并行修改后旧通过结果不会自动成为新版本的通过结果。

来源标记：**自有**＝当前项目实现；**上游**＝Milkdown/ProseMirror/CodeMirror 实现；**宿主**＝依赖浏览器或系统默认行为，必须实测确认。证据栏“有用例”仅表示已找到测试代码，不保证当前工作区运行通过。

## 每个操作的共同边界

不把所有维度暴力相乘。先覆盖单因素，再优先组合已出过问题的因素；这些组合比继续堆同类正常输入测试更容易发现缺陷。

| 维度 | 必测取值 |
| --- | --- |
| 位置 | 块首/中/尾，文档首/尾，折行处，空块，前面含引用定义或 HTML |
| 选区 | 空光标、块内选区、跨格式、跨块、反向选区 |
| 上下文 | 正文、格式边界、行内源码展开、列表/嵌套列表、引用、表格、代码 |
| 内容 | 空内容、首尾空格、空行、转义、实体、中文、emoji/组合字符 |
| 操作节奏 | 单步、连续重复、快速切换、长停顿、失焦后继续、中文组词中 |
| 会话 | 撤销/重做、保存/重开、切模式、切标签、前文变长/变短 |
| 环境 | 浏览器、macOS 原生、Windows 原生；各自的快捷键和输入法 |

优先交叉组合：**行内源码收起→空列表项删除；前文长度变化→撤销→继续输入；跨块选区→粘贴→撤销；格式行尾→方向键→输入；组词→滚动/失焦→确认；表格末格→Tab→撤销。**

每个用例的通过条件：文字正确；光标/选区正确；视口没有非预期跳动；保存结果正确且未修改区域保真；撤销/重做恢复预期状态；无新增错误。格式操作允许必要的语法变化，不能机械要求操作前后源码完全相同。
