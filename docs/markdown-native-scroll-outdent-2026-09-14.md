# Markdown 原生源码跳动与减少缩进验证（2026-09-14）

本次范围为两个问题和一个横向检查要求：实时预览左侧源码编辑时跳动；阅读编辑中列表续段 `sdf` 无法顶格；检查普通列表、任务、引用及连续标题的相同问题。用户明确要求自建大型复杂文件，并打包到本机验证，浏览器通过不能替代原生结果。

## 原生滚动问题

自建 `complex.md` 共 4,469 行、404,808 字节，含 100 组长中英文正文、嵌套引用和任务、长表格、100 组 TypeScript 围栏、数学、脚注与 10 个 Mermaid 图。原生使用其 `native-complex.md` 副本；现场另含用户演示输入，最终为 4,475 行，未改用户提供的原文件。

旧包在第 246 行长表格处点击、单键输入 `b`，输入前源码顶部约第 234 行，输入后画面跳到第 1 行，而状态栏仍在第 246 行。前后分别获取原生截图，没有重新定位编辑元素。这是 macOS 应用中的实际复现；浏览器此前同类操作未复现，不作为本问题通过证据。

原因是预览替换 HTML／异步渲染时也会产生滚动事件，它经双向同步反过来拉动源码。`PreviewScrollIntent` 记录预览侧实际滚轮、触摸、鼠标和翻页按键；源侧输入或预览更新会清除该意图。同步回调及排队的下一帧均检查意图，程序同步不会再被作为用户滚动回传。预览目录、搜索的显式跳转保持原有路径。曾考虑的单纯 200ms 延时方案已撤回，不是最终实现。

修复后的 macOS 包实测：

- 相同第 246 行长表格输入、回车拆行、退格合并，源码仍留在原处，没有回到文首。
- 右侧主动向下滚动一页，左侧正常同步到后续代码行。
- 手动滚动到第 2,152 行长正文，逐键输入 `7`、`8`、`9`，视口和正文屏幕位置保持。保存后逐字节核对，只有该处插入 `789`；一次 Cmd+Z 后保存与输入前完全一致。
- 拉丁字母部分操作出现原生预编辑选中状态，仅记录实际显示，不将其算成真实中文组词验收。Windows 与完整 IME 候选操作未新增结论。

## 减少缩进与横向检查

原文件文末为同一列表项下的续段／标题，修改 H2 层级本身不会退出列表。新增中英文工具栏“减少缩进 / Decrease indent”，和 Shift+Tab 共用命令。标题行首 Backspace 也可先退出所属列表／引用，保留标题级别。续段仅提升当前选中块，前后内容继续保留在列表内；首段仍沿用原有整项与任务缩进逻辑，表格和代码不误用该命令。

横向检查另复现连续两个标题时前一个仍无法提升：拆开后的列表项必须以段落开头。现将后续列表的空段落标记与提升合在同一撤销事务，保留后一个标题及正文。该边界下后续列表会出现空列表标记，这是保留其列表归属所需的结构，并未将未选中标题一起顶格。

原生验收使用 `native-indent.md`、`native-consecutive.md` 自建样例：

- `sdf` 用工具栏顶格及行首 Backspace 顶格，仍是 H2；前面的 keep/continuation 与后面的 following 保留列表结构。
- 引用标题通过 Shift+Tab 退出引用，前文 quote 仍在引用内。
- 连续标题单独顶格后，下一个标题仍嵌套；任务列表内标题也可单独退出。
- 保存源码检查、一次撤销保存逐字节恢复通过；最终连续标题结果关闭重开后仍为根级 H2，后续内容完整。
