# Markdown 输入与后台预览性能（2026-09-12）

用户要求继续优化。本轮限定三处：历史差异扫描、同一文档状态的重复源码坐标查询、隐藏 Markdown 预览重复生成。主任务负责坐标、整合及浏览器验证；两个 agent 分别处理历史算法和后台预览。未提交推送，未修改其他任务的列表/表格/保存行为。

## 改动和边界

- `markdownSession.ts` 的 `sourceChange` 用 1024 字符分段原生字符串比较跨过长公共前后缀，再按原 UTF-16 规则计算边缘。返回的 from/removed/inserted 与原算法完全一致，因此不改变 750ms 分组、组合输入、来源边界和撤销数据。没有扩大成修改 store/document 的 patch 接口。
- `markdownVisual/document.ts` 的 `sourceOffset` 缓存当前 doc、AST、原文组合下的最多 32 个位置。历史会重复请求空选区两端，发布光标还会再次请求同一位置；命中直接复用，保留原来的定位算法。apply、project、reset、restore、行内源码、同一 PM 文档不同原文/AST 都能失效。没有引入新的近似定位。
- `Preview.tsx` 只在 Markdown 实际可见且保留 DOM 时生成新 HTML；隐藏期间取消未启动的定时任务，忽略迟到结果。激活时使用最新源码、路径、主题和公式设置，参数没变直接复用现有结果。未传 active 的独立 Preview 仍可见，非 Markdown 路径保持原行为。已经开始的图表继续完成，隐藏主题不会重新启动图表；HTML 更换/卸载仍按原逻辑清理。没有新增跨模式全局 HTML 缓存。

代价：历史比较创建短暂子串；每个 MarkdownDocument 最多保存 32 个位置；每个保留 Preview 多保存已渲染源码的引用及少量参数，可能延长旧字符串存活时间。有变化的隐藏槽激活后仍使用现有 80ms debounce，首次定位仍按全文规则计算。

## 五轮验证

### 轮 1 — 普通行为和规范差异

期望：相同前后原文产生完全一致的修改范围；空选区重复定位不改变结果。

实测：6,449 个 sourceChange 等价样例，以及普通编辑、邻接分组、混合来源、100 次编辑撤销/重做通过。坐标测试在真实 Milkdown schema 中逐位置对照原函数，累计 31,958 次通过。结果：通过。

### 轮 2 — 边界与缓存失效

期望：UTF-16、CRLF、重复文本、1024 边界、空文、源码保真、坐标缓存替换安全。

实测：组合字符/代理项/实体/末尾空白、区间重叠、全替换和无变化均相同；复杂 Markdown、任务/引用/表格/代码/公式/原始 HTML/脚注/行尾 HTML 的位置一致。apply/project/reset/restore/editInline、同 doc 不同 AST/原文，以及缓存数量上限通过。结果：通过。

### 轮 3 — 后台与异步组合

期望：隐藏时不重复生成，激活不会拿错文档或主题，取消不破坏原有图表生命周期。

实测：`test-preview-visibility.mjs` 11 组通过，含默认可见、连续隐藏更新、冷 DOM、空文、最新公式设置、修改后恢复、定时取消、迟到结果、多标签、主题与正在进行的图表、卸载、非 Markdown。真实浏览器双标签使用实际 Shiki/Mermaid，验证隐藏源文/主题不改旧 DOM、激活最新暗色代码、冷 DOM 最新原文和最终原文精确恢复。结果：通过。

### 轮 4 — 真实长文与历史/呈现

期望：编辑、保存、跨模式历史和恢复光标不因缓存改变；共享显示一致。

实测：固定源码开发页 6303 行文末实际输入 q/w/e，原文增量为 3 字符、保存快照逐字一致；源码模式三次撤销恢复全文，阅读模式三次重做精确恢复，撤销后输入 z 仍在第一次编辑的位置。最后撤销、保存、标签往返原文一致。复杂文档亮/暗各 1374 项呈现对照无差异。结果：通过。

页面热更新前一条输入未产生 beforeinput/input，已排除；随后全部使用固定快照重做。快照初次静态字体请求因临时目录的开发服务白名单受限，补齐快照内 node_modules 静态资源访问后才进行最终验证，未修改产品 Vite 配置。

### 轮 5 — 全量性能/功能/构建

`perf:markdown-input` 已接入 `perf:all`，包括历史、坐标及后台专项。完整 `perf:all` 独立运行通过，包括原有前端与 Rust 性能套件。本轮同快照 BEFORE/AFTER 构建及后续含并行更新的独立快照生产构建通过。

第一次性能运行与构建、功能回归同时进行，标签切换 p99 为 17.63ms，超过 16ms 阈值；停止并发重负载后同命令复测为 1.30ms，套件通过。保留失败和复测日志，没有改阈值或删除用例。

第一次功能回归发现图片对照 fixture 传 active:false，却意在显示可见 Preview。已改为独立默认可见（仍不接管窗口快捷键），全部图片断言不变，专项和后续图片集成通过。第二次运行时并行任务修改了首任务 Tab 行为，旧导航断言失败；随后该任务更新对应断言。为避免移动中的源码/测试混用，复制包含当前三项优化的完整固定快照，并隔离测试生成目录后重跑。

最终固定快照 `npm run test:all` 退出码 0：62 核心、106 阅读集成、144 通用组件、119 XMind、13 导出及所有操作/导航/任务/跨块/保存/语法/代码/图标专项通过；其中 7 组导航、18 组任务和 12 项代码聚焦检查通过。结果：通过。该结论对应已记录 SHA-256 的固定快照，不代表之后继续变化的并行工作区自动通过。

## 剩余优化

本轮没有解决首次源码坐标查找的全文遍历、AST 后续节点绝对位置复制、定义密集文档的上下文拼接；这些比继续扩展小缓存更值得单独测量。模式切换的大 DOM 显示、主题/语言/路径触发阅读实例重建、跨模式 HTML 结果复用，以及打开状态的标题/搜索增量索引、未变 SVG 复用也仍在范围外。

下一轮建议先单独剖析长文输入到绘制之间的成本，再决定做 AST 偏移或 DOM 显示优化。当前同标签阅读实例已保留，关闭搜索/大纲已停算，不能再把这些当成尚未优化的项目。

原始日志、五轮数据、浏览器结果和快照位置记录在 `tests/artifacts/markdown-input-performance-2026-09-12/`（被忽略）。可重跑入口为 `npm run perf:markdown-input`，浏览器专项为 `tests/markdown-preview-visibility-review.html` 及既有长文/呈现页。未新增真实 IME、macOS/Windows 安装包或长期压力结论，没有启动原生应用；结束时关闭本次测试页和两个开发服务。
