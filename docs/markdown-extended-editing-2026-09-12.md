# Markdown 非导出扩展实施与验收

用户要求继续处理与 Typora 的差距，排除导出、统一字体、使用完整复杂 Markdown 验证。本任务没有执行提交或推送；收尾检查时共享工作区 HEAD 已变为 `840e863`，功能代码已包含在该提交中，本文还有未提交的验收记录更新。此前检查记录中的缺口属于当时状态，请结合本文阅读。

## 已实施

- **脚注与提示块直接编辑**：扩展现有 Milkdown 节点，不再把普通带脚注段落、脚注定义和标准提示块整体转成源码块。保留引用标识、原有提示标记拼写、CRLF 和未修改内容；结构修改可正常序列化。脚注顺序编号、定义内再次引用、重复引用的各个回跳入口、点击跳转和原生文字悬停说明随内容更新。页边提示只随光标出现。
- **语法简写**：阅读编辑与 Preview 支持 `==高亮==`、`H~2~O`、`X^2^` 和 `:smile:`。使用 markdown-it 的高亮、上下标规则和表情词表，remark 高亮扩展以及对接相同上下标规则的词法扩展。逐键输入、保存重开、转义、未知名称、代码围栏和行内代码均有测试。单个 `~` 用于下标，`~~` 保持删除线。
- **图片目录与整理**：源码粘贴和阅读编辑本地上传都读取 YAML 的 `typora-copy-images-to`，支持 `${filename}`。仅接收文档目录下的子目录；错误 YAML、别名、绝对路径和父目录回退全局设置。写作设置新增本地图片整理，复制后统一更新 Markdown、引用式和 HTML 图片路径，同一文件只复制一次，保留原文件；网络图片跳过，失败保留原引用。所有读写仍走 Rust IPC。
- **长文收起**：未修改片段恢复缓存；修改过的普通单行正文/标题仅重解析当前块，并带上引用定义。多行和复杂结构继续用完整解析，避免损坏边界。每组 5 次、1000 段/34,889 字符的 JSDOM 实际控制器测量：旧完整解析路径中位数 93.51ms，局部路径 1.46ms，完整文档解析次数从 6 次降为 1 次。不是整篇编辑器输入或原生 IME 延迟。

## 测试中发现并修复

1. 新建脚注 schema 被原有 schema 抢先匹配，造成编号缺失：改为扩展原节点。
2. CRLF 以及 Milkdown 将软换行提前转为 break，会留下提示块首行空白：统一剥离标记与对应换行，源码偏移保留。
3. 上下标词法在生产模式测试通过，但开发模式断言失败：补齐闭合标记 token；加入开发条件运行和完整复杂样例加载检查。
4. 完整带公式样例暴露 KaTeX 包的 Node/CJS 双层 default 兼容问题：懒加载同时兼容两种导出形态。
5. 提示块两侧 DOM 结构不同：Preview 使用与直接编辑相同的标题/正文结构和共享 CSS。

### 原生输入复测补充：尚未形成可重复的 IME 验收
