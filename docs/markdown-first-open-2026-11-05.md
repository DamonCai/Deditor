# 长 Markdown 首开优化记录

本轮直接来源于当前会话用户的继续优化指令。对照基线为 `ee479ea`，不包含渐进显示、文档截断或关闭正文交互。

## 改动

- 初始化期间复用原始语法树。每个消费者拿独立克隆，避免块转换相互污染；最后一个初始化结束或失败即释放。最多保留两个源文本，总计不超过 512 Ki UTF-16 单位；每份限定为 48–256 Ki 单位。
- 同一套原始语法解析器移到专用 Worker，与 Milkdown 初始化并行。保持主线程原解析作为创建失败、传输失败、解析失败和 1500 ms 超时的回退。空闲预热，60 秒无请求后终止 Worker。
- Worker 使用实体解码依赖的无 DOM 入口，避免浏览器入口调用 `document.createElement` 后静默回退。没有引入另一套 Markdown 文法。
- DOMPurify 直接返回 DOM Fragment，省去净化后的 HTML 再序列化、再解析；保留原有选项和内嵌页面处理。

## 同机对照

同一台 macOS/arm64，同一个原生 WKWebView 生成样例工具，相同窗口、输入和完整正文。计时从文件树点击到编辑器可编辑并完成原生快照；禁用额外保留槽，分别启动修改前、修改后进程。数据是三份不同文档的首次渲染，不能作为延迟分位数或所有报告的保证。

| 样例 | 修改前 | 修改后 | 解释 |
| --- | --- | --- | --- |
| 2802 行、100 张表格，首次渲染中位数 | 2401 ms | 1899 ms | 减少 502 ms，约 21% |
| 同组逐份首次渲染 | 2401 / 2326 / 5092 ms | 1899 / 2421 / 1852 ms | 有 GC/原生排版波动，第二份未加速 |
| 同组保留视图返回中位数 | 372 ms | 445 ms | 本轮未证明热切换改善；观察值增加 73 ms |
| 修改后：2282 行、公式和代码块 | — | 1512 / 932 / 692 ms | 第一份仍超过 1 秒 |
| 修改后：1442 行、图片、HTML 和代码块 | — | 769 / 481 / 494 ms | 本样例首次渲染在 1 秒内 |

表格对照的 WebContent 采样 RSS 最大值为修改前 1107.6 MiB、修改后 938.6 MiB。采样值不是峰值，也未包含独立 Worker 全部内存，不能据此声称总内存下降。额外代价包括约 299 kB 的解析 Worker 产物、Worker 运行时及初始化期的临时语法树；Worker 与临时树均有释放边界。

证据位于本地忽略目录 `tests/artifacts/extreme-open-20261105/`：`comparison-{before,after}-quiet.log`、`final-report.log`、`final-mixed.log`。首次对照曾与另一项回归并行，未将其作为上表最终结果。

## 剩余限制

全部长报告首次打开小于 1 秒的目标尚未完成。主线程仍须建立 Milkdown/ProseMirror 模型、完整 DOM、恢复焦点，并由 WebKit 排版与计算事件区域。后台解析不消除这些工作。本轮不宣称达到性能上限。

已试的改变滚动根、裁剪区域、延后焦点恢复、滚动容器合成层隔离没有稳定收益，未进入产品。合成层实验首份 2379 ms，后两份 1707 / 1531 ms，首份变慢，不足以证明整体改善。将原始语法树直接替换 Milkdown 的解析结果尚无完整文法等价证据，也未进入产品；不能为节省一次解析而冒险改变 Markdown 语义。
