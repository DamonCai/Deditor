# 全局搜索首次打开文件的高亮与居中修复（2026-09-21）

## 问题与修改

用户反馈 Command+Shift+F 点击结果后，新打开文件没有高亮，已打开文件正常。
原实现每帧尝试定位，最多 120 帧；首次加载包含异步模块加载及阅读编辑器初始化，超过等待次数后请求被静默丢弃。自建测试将阅读初始化延迟 2.4 秒，修复前实际选区为空，断言失败。

改为监听目标编辑器就绪与当前文档状态，不依赖帧数截止；就绪后下一帧设置匹配选区并居中，避开初始化光标恢复及搜索弹窗关闭的焦点恢复。阅读模式明确等待阅读编辑器，源码模式使用对应 CodeMirror。
定位由独立模块持有，能够跨越 App 关闭搜索弹窗时的组件卸载；成功后解除订阅。重新搜索、离开目标文件或改变面板/模式时取消旧请求，防止迟到定位抢走焦点。保持既有高亮样式与中英文文案。

## 阅读编辑显示高亮补充（用户再次反馈后）

用户明确已重新打包，且搜索前就处于阅读编辑。上次仅处理就绪等待；全局搜索调用 navigate 设置的是原生选区，没有写入阅读编辑的搜索装饰。已有测试只断言选区文字，不能证明焦点离开/源码收起后的持续高亮。此次不再把这两者混为一谈。

阅读 navigate 现在同时设置独立的命中装饰，与页脚搜索状态分开；启动后的空搜索效果不会清掉它。普通正文复用现有橙色 current 样式，代码块同时支持展开的 CodeMirror 和收起的 Shiki 展示，并在 DOM 更新或显隐变化后重绘。清除原生选区、失焦不会清掉命中标记；用户在正文按键/点击、实际修改正文或开始新的有效页脚搜索时清除，装饰不进入正文与历史。
