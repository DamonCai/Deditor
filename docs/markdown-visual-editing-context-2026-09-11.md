## 最终架构倾向

**以 Milkdown／ProseMirror 为基础定制 Markdown 可视化编辑，保留 CodeMirror 源码模式，独立建设 Markdown 保真文档层与每标签编辑会话层。**

| 层次 | 职责 |
| --- | --- |
| 可视化编辑层 | 复用 Milkdown 的成熟能力；利用 ProseMirror 定制正文、列表、表格、图片、公式及图表交互，适配 DEditor 外观 |
| 源码编辑层 | CodeMirror 负责完整 Markdown 源码；可视化页面内的代码块也可内嵌 CodeMirror |
| Markdown 文档层 | 保存原文、语法结构、源范围和位置映射，处理修改范围回写、未知语法保留及外部文本更新 |
| 编辑会话层 | 按标签管理内容版本、修改记录、撤销归属、视图选区与滚动锚点，协调保存、源码/可视化切换及外部变更 |

阅读与可视化编辑应共用呈现组件，阅读状态关闭编辑能力，切换尽量保持排版和位置；源码是独立视图。现有分栏预览、目录、查找及导出需要在实施时明确适配方式，不能因新内核接入静默删除或降级。

所有编辑入口经过同一会话提交修改，不依赖两套编辑器互相覆盖整篇字符串。Markdown 原文是落盘依据，富文本 JSON 不能成为唯一存储。源码和可视化编辑的不同位置体系及历史记录需要明确协调，不能简单同时打开两套独立 undo 栈就宣称跨模式撤销已解决。

优先复用成熟组件，按实际交互和保真差距定制；如果具体封装阻碍需求，可在该处深入 ProseMirror，而非提前重写所有基础功能。本项目现已接入并完成自动化与浏览器交互验证；双平台与真实输入法证据仍需补齐，具体以实施记录为准。

## 讨论过但未作为最终选择的路线

- 预览点击段落后局部改源码：适合快速实现顺手修改，不是用户最终要求的连续编辑体验。
- 纯 CodeMirror 装饰实现实时预览：最初因复用与改动量而推荐；用户更重视完整可视化编辑效果后，最终建议已调整。
- 直接从 ProseMirror 底层搭建全部能力：讨论过其定制空间，但更多底层控制不自动等于更好的效果或稳定性。最终倾向是 Milkdown 起步、针对性深入 ProseMirror 定制。
- 给当前预览 HTML 加 contenteditable：缺少可靠的编辑模型、源码映射、撤销和光标保持，不能作为完整实现。

## 目标交互

| 内容 | 目标体验 |
| --- | --- |
| 正文、标题、粗斜体 | 保持排版效果，点击后自然输入，支持跨段选择与删除 |
| 列表、引用、任务列表 | Enter 续写、Tab 调整层级、勾选同步为 Markdown 修改 |
| 表格 | 单元格直接编辑、键盘导航、增删行列和对齐；适配已有表格内列表扩展 |
| 链接、图片 | 小型编辑浮层；编辑模式普通点击不会误跳走；本地图片路径保留 |
| 代码块 | 块内直接编辑、高亮、语言选择，与文章历史协调 |
| 公式、Mermaid、PlantUML | 显示渲染结果；进入编辑显示源码，退出恢复结果；异步渲染不丢选区、不错误跳动 |
| 未识别语法 | 保留原文并提供可恢复的源码编辑入口，不静默吞掉内容 |

外观沿用 DEditor 字体、主题、工具条和阅读宽度，形成连续文章编辑体验；新增文案中英文同步。可见控件与键盘操作都要实测。

## Markdown 保真要求与难点

- 打开或只切换模式，不应产生文件修改或重排整篇 Markdown。
- 未编辑范围保留原样是验收目标；不承诺普通 AST/序列化器自动逐字节保真。
- 保存源文本与语法范围，优先回写受影响部分；列表重组、引用定义等跨范围关联可能需要扩大回写范围，不能只做朴素字符串替换。
- 验证空行、缩进、换行符、转义、列表符号与特殊编号、引用链接、HTML 颜色/高亮、表格内列表、公式和图表围栏。
- `.mdx` 当前也被归为 Markdown；其 JSX/扩展语法的支持边界必须单独确认并保护原文，不能默认完整支持。
- 未知 HTML、未知节点和不完整输入必须有保留策略。保持内容语义与保持原文格式是不同要求，应分别测试。
- 保存时格式化是现有独立选项；验证保真时区分编辑器自行重写与用户启用的格式化，明确二者如何协调。

以下来自此次代码核对，后续实施前以实际源码和 Git 状态复核，不把历史概览当作最新实现。

| 位置 | 观察与后续要求 |
| --- | --- |
| `src/App.tsx`、`PreviewModeSwitch.tsx` | Markdown 与 HTML 共享 `showPreview / previewMaximized`；Markdown 新模式需独立表达，避免改变 HTML 布局与开关行为，并处理旧持久化状态 |

| `src/components/XmindView.tsx`、`src/lib/xmind/` | XMind 有专用文档模型、历史和归档写回；本次 Markdown 升级不重构它，不覆盖 XMind 未完成工作 |
| `src/components/Editor.tsx`、`EditorHost.tsx` | 现有文件类型分流、编辑器保留与回收策略需要保留；新会话不能让 HTML/XMind 切标签时意外重挂载、丢历史或抢焦点 |
| `src/lib/editorBridge.ts`、`MarkdownToolbar.tsx` | 当前命令直接操作 CodeMirror，阅读模式禁用编辑；增加当前 Markdown 编辑器适配，同时保留其他代码工具条原路径 |
| `src/lib/documentFlush.ts`、`fileio.ts` | 保存/关闭前按标签提交草稿，XMind 已使用这一机制；Markdown 接入后先提供最新文本快照，保留文本与二进制写入分流。当前 flush 回调同步，新实现不能悄悄返回未等待的异步序列化 |
| `src/lib/persistence.ts`、`fileWatch.ts`、`src/store/editor.ts` | 保存草稿、dirty 判定、重启恢复、格式化、外部变更需要适配；不要把编辑器实例或不可序列化状态直接写入持久化数据 |
| 快捷键、原生菜单、样式与性能 | 只有活跃编辑器接收命令；CSS 限于 Markdown 容器，新内核按需加载并有缓存/回收策略，检查启动、内存和切标签开销 |

1. 读取本上下文、适用的 AGENTS.md 和实际 Git 状态，确认当前依赖及公共接口，保护既有改动。核对官方 API 和版本，锁定依赖；不要依据讨论中的示例直接假定 API 可用。
2. 先做隔离的可运行验证，优先攻克原文保真与跨模式撤销。准备自建普通及复杂 Markdown 样例，验证中文输入、表格、图表、保存回读、源码切换与长文档性能，再决定正式接入细节。
3. 建设每标签编辑会话与文档层，明确权威内容版本、事务来源、历史策略、位置映射以及程序性更新的处理；逐步接入可视化组件、工具条、查找/目录、保存/自动保存及外部变更。
4. 完成目标交互和兼容性；分别记录自动化、浏览器及原生验证证据。真实 IME 候选与组合输入、macOS/Windows 差异必须实测，粘贴中文不等于 IME 通过。
5. 混合回归：修改 Markdown → 修改 HTML 并预览 → 修改 XMind 节点 → 分别撤销/保存 → 关闭重开；覆盖自动保存、另存、未保存提示、会话恢复与快捷键焦点隔离。
6. 对应最终源码完成构建与交付验证，记录尚未验证的项目。原型通过或单元测试通过不能代表成熟 Typora 手感、全量语法兼容或双平台验收已完成。

测试仅用本轮自建样例或用户提供的文件，不扫描真实文档/历史状态。性能用测量结果判断，初始不承诺未经验证的阈值；应关注输入延迟、模式切换、长文档加载、图表异步渲染、多标签内存及非 Markdown 文件启动开销。
