## 已修复的性能与功能问题

- 行内源码仅移动光标也重建 AST；现依据最终文档身份跳过无修改事务，并优先从选区/原位置寻找投影，结构变化保留回退。1000 段、20 次移动五轮中位数 11.554→1.539ms（-86.7%）；20 对中文插删 36.083→29.060ms（-19.5%）。保留全部 40 次实际写入。详见 [行内优化](markdown-inline-performance-2026-09-22.md)。
- 预览每次下一命中修改所有高亮，现只更新前后两个；10,000 命中连续 100 次导航的 class 操作由 1,000,000→199，重复选中仍执行居中。
- 保留块重复解析全文、上下文片段重复创建全文 DOM，改为共享当前上下文，保持输出字符串与每个实际预览 DOM 独立。组件前后数据与缓存代价见最终验证节。
- HTML 保留作者 base target，转换显式本地 base、表单、响应式图像及 SVG href。实际浏览器发现 JSDOM 未暴露的 xlink namespace 漏转换，已改命名空间读写，最终两张图真实显示。打开失败有中英文原因反馈，近期文件保持局部提示，失败不记入系统最近列表。详见 [资源检查](html-local-resources-audit-2026-09-22.md)。
- Mermaid 继承的 50,000 字符/500 边门槛会用错误图替代或拒绝合法输入，已解除这两项本地渲染门槛，保留队列/取消与错误源码。50,073 字符真实样例修复前显示 Maximum text size，修复后完整 50,041 字符标签；501 边样例前失败、后通过，亮暗各两张 SVG、0 错误、合计 502 条边。

## 真实浏览器采样

同一 34,641 字符、100 节复杂文档和测试专用采样器，逐键 a/b/c/d/e 后撤销，修改前后源码精确一致。阅读行内输入从 keydown 到第二帧五次样本中位数 24.3→23.1ms；此微小差异受绘制/后台负载影响，不当作稳定整体提速。最终源码输入五次第二帧中位数 15.4ms、实时预览输入 12.3ms；后者仅输入反馈，不代表异步预览全部完成。源码首次切换就绪+下一帧 57.4ms、实时预览 283.8ms，单次数据不冒充 p95。

修正测试页计时器的共享事件数组：快按时旧 frame2 会混入新按键。现在每键独立记录；冻结基线同步使用同一采样器后重新测量，旧混杂样本不计入上述结果。

千节样例实际 299,244 字符、1001 个表格、84,665 个 DOM 节点。初次浏览器读取和截图明显等待，后续用组件 CPU 采样定位；不能直接把 CUA 超时/截图时长当作产品耗时，也没有据此加文档大小限制。有限 JSDOM idle 观察未发现持续事务/observer 循环，但大量节点初始化与真实布局仍有成本。

## 保留的必要边界

HTML 继续通过不同源独立文档保护主编辑器，保留作者自己的 CSP；网站自己的嵌入规则和 WebView 权限不能由编辑器覆盖。文本仍采用现有 UTF-8 保存模型，非 UTF-8 明确报错，不猜编码后静默破坏保存；CSS/脚本动态构造的显式 file URL 不在本轮属性转换覆盖内。Markdown/HTML 文本打开没有本轮新增大小或扩展名门槛。

8 个保留视图和高亮缓存预算只淘汰可重建视图，不限制文件数量或正文；历史 2MiB/版本等为 UI 明示的版本保留策略，不影响文件打开编辑。未为性能隐藏正文、跳过语法、减少撤销或关闭 HTML 交互。

本轮不新增 Windows、真实中文候选、真实图床、远程 PlantUML 大图、长期 WebView 内存结论。大规模冷加载、全部展开的历史 DOM、超缓存标签恢复等持续压力边界仍需单独实测，不能以单测全绿保证任意规模无延迟。
