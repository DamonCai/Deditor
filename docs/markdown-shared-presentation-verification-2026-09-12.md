# Markdown 共享展示实施与验证（2026-09-12）

用户要求阅读编辑与实时预览统一显示，并明确要求执行共享组件方案。本次已完成共享展示层接入、实际差异修复和相关回归；没有提交或推送，没有扩展导出功能，也没有修改独立 XMind 功能。

## 实施

- `MarkdownDocumentSurface.tsx`：Preview 与阅读编辑共用的显示外壳，统一文章主题、字号及缩放参数。阅读编辑下的 ProseMirror DOM 保持原实例，设置变化不重新挂载正文。
- `markdownDisplay.ts`：Preview、代码/图表 NodeView、保留块 NodeView 共用 HTML 清理、图表源码元数据保留、本地图片解析及 Mermaid/PlantUML 后处理。统一取消入口；宿主仍保留过期结果校验、源码复用及编辑占位高度。图片根目录变化可以单独更新，不重启整篇图表。
- `preview.css`：原字体栈、正文宽度、行高、块间距及列表/表格/图片参数共用。`markdown-visual.css` 只保留编辑控件、光标提示、源码编辑区和 DOM 包裹适配。脚注浮层继续共用此前的富文本安装函数。
- 可编辑内容仍由 ProseMirror 管理，实时预览仍使用 markdown-it 及源码行定位；没有将整个编辑器加载到预览，也没有让 React 重写输入中的正文。

复杂文档实测发现并修复三处原有差异：

1. Milkdown 表头与正文同处 tbody，表格隔行底色偏移一行。共享规则现在按非表头行计数，两端一致。
2. 窄窗下阅读编辑继承 `pre-wrap`，代码块多换行、高出预览 45.5px。共享代码块规则明确使用 `white-space: pre`，横向滚动和高度一致。
3. 嵌套列表包裹造成每层约 2.25px 的间距损失，后续表格逐渐错位。适配层使用共享间距差额补偿边距折叠，整体块位置一致。

## 仍需单独验收

本次共享展示重构完成，不等于 Typora 全面对齐。真实 macOS 中文组词、Windows、真实图床账户和原生目录选择器仍按此前记录保留未验收状态。脚注定义在阅读编辑中保留原文位置，在实时预览中集中到文末；这是编辑布局边界，正文编号与样式共用。
